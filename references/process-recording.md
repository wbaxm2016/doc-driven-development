# 过程记录：一次会话一份双侧档案

## 三条硬规则

1. **过程不构成约束**：档案 `authority: 4` + `status: snapshot`。要让它成为约束，必须回写契约或新开 ADR。
2. **只记要点，不逐字转录**：原话摘句 ≤ 2 行；档案是索引，不是录音。
3. **发现即登记，不打断**：问题进收件箱后继续当前话题；用户不需要在对话里回应。

## 七段结构（顺序不可变，脚本会校验）

1. 本次范围（要解决什么 / **明确不做什么** / 承接上期）
2. 用户侧记录（分类表）
3. AI 侧记录（六项）
4. 决策与选项对比（八维表）
5. 开放项
6. 本次产出
7. 交接（下次从这里开始；**首行必须是「下一步：<计划任务编号>」**）

## 用户侧 8 类（一条消息可拆多类）

| 码 | 含义 | 落点要求 |
|---|---|---|
| `Q` | 提问 / 质疑 | 答在哪一段 |
| `R` | 需求 | 哪个 REQ / 哪份契约（**未入表要写明**） |
| `F` | 功能 | 哪个组件 / 哪条工作 |
| `E` | 实现探讨 | 结论或待决项 |
| `D` | 决策 | ADR 或档案 §4 |
| `C` | 确认 / 否决 | 被确认或被否的那一条 |
| `X` | 明确排除 | 排除理由（防以后重复提） |
| `O` | 其它（偏好、语气、边界） | 写进规范或偏好记录 |

每行都要有落点。"未定的决策"必须**同时**进 §5 开放项，否则会烂在档案里。

## AI 侧六项（缺一项，档案就不可对照）

1. **需求理解**：我把它理解成什么；与用户原话的偏差显式写出。
2. **实现思路**：为什么这样做；否决了哪些做法。
3. **组件归属**：落在哪个组件/文件/函数，对应哪个 REQ 或 ADR。
4. **系统位置**：依赖谁、被谁依赖、不参与哪条链路。
5. **gap 四列**：`期望 / 现在 / 证据 / 缺口`。**没有证据只能写"未核实"**，不许写"应该没问题"。
6. **本轮提出的问题**：`ISS` 编号 + 一句话。

## 决策对比：八维，允许"两者相当"

语义正确性 · 实现成本 · 改动半径 · 可逆性 · 长期维护 · 用户可感知 · 可验证性 · 风险

**保持开放性**（这是本实践最容易退化的地方）：

- 未采纳选项**不删**；写清"当时为什么没选"；
- 每条未采纳项给**回条件**（什么事实出现就该重新考虑）+ **触发信号**（可观察的）；
- 结论区写"选 X"和"**是否暂定**"；暂定必须带回条件。

## 问题收件箱

| 字段 | 要求 |
|---|---|
| `ID` | `ISS-nnn`，只增不复用 |
| `类型` | 缺陷 / 口径冲突 / 文档债 / 风险 / 待决 / 机会 |
| `影响` | 不处理会怎样，**具体到可感知的后果** |
| `状态` | `open` / `decided` / `deferred` / `done` |
| `落点` | 处理它的 ADR / 文件 / 计划任务 |
| `回到条件` | `deferred` 必填 |

**收件箱不是待办清单**：只保证"不会被忘掉"，排序由计划文档负责。
`done` 的条目移到「已闭环」表并**从主表删除**（否则编号重复会让校验报错）。

## 收尾动作（关会话语义）

1. 每场开发会话开头：`python scripts/devlog.py new --title "主题"`。**轻档**改动（只改措辞、错字、格式、注释，不碰契约/ADR/计划/码表/脚本行为）不建档，只跑改动触及的校验——判据见 `SKILL.md` 硬规则 12，分级不豁免任何检查。
2. 过程中：用户侧分类边聊边记；AI 发现问题立刻进收件箱。
3. 收尾：填 §3/§5/§6/§7 → `devlog.py check` → `devlog.py index` → 回写计划文档状态。
4. 交接段必须能独立读：**首行是「下一步：<任务编号>」**（编号必须存在于计划 §5；计划全部完成时写「下一步：无」）、现在在哪、别踩的坑、读哪几篇。`devlog.py check` 的 `S8` / `S9` 会校验锚点与计划表是否对得上。
