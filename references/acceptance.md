# 验收清单（1–50）

> 从 `SKILL.md`「验收」迁出（2026-11-16 定期减法，硬规则 16）：这是 `scripts/self_test.py` 的规格来源，改脚本 / 加断言前对照读；`SKILL.md` 只留指针（一处一个权威）。


1. `doc_init.py` 铺完，`doc_check.py` 为 `errors=0`。
2. `devlog.py new` 能建出编号与文件名正确的档案。
3. 故意制造断链、ADR 缺段、`summary` 超长、ISS 重复、分值越界——五种错误都能被报出。
4. 改任一任务行后 `plan.py index --check` 报过时；重跑 `index` 后转为 up-to-date。
5. 时间线按日期倒序列出全部会话，链接可点。
6. 把某篇契约的「必须」删掉 → E13 报；把 `superseded_by` 指向不存在的 ADR → E15 报。
7. 在 `docs/文档` 而不是 `docs/` 下铺骨架 → `doc_check --docs 文档` 通过，`devlog.py` / `plan.py` 不报假通过。
8. **跨天**：铺完骨架后把 `会话档案模板.md` 的日期改成昨天（模拟"骨架是昨天铺的"），再 `devlog.py new` → `check` 必须 0 error，文件名前缀 = `<session_date>-<session_no>-`，时间线日期列与档案标题同一天。2.0.0 就是缺这一条：`doc_init` 把模板里的 `{{DATE}}` 烤死在铺骨架那天，第二天起每次开档都自相矛盾。
9. 前置写一个表里不存在的编号 → `plan.py check` 报 `[P11]`；工作表方向列写 `D9`（方向表里没有）→ 报 `[P12]`。查不出这两条时，任务会被永久标 ⛔ 且没有任何诊断。
10. 把 `_schema.json` 改成非法 JSON → 四份脚本（`doc_check` / `devlog` / `plan` / `verify`）都给 `exit 2` + 一行说明（不是回溯）。
11. 把某条需求 `verify:` 指向的测试改成必然失败 → `python scripts/verify.py` 退出码 1；状态=`待实现` 的行跳过。
12. **改动分级不改变校验结果**：只改一段正文的轻档改动，`doc_check` 的 `errors/warnings` 与改前一致；在同一处制造断链、删掉条款的 `verify:` → `E7` / `E18` 照报；`SKILL.md` 硬规则里恰有一条这样的体量判据。
13. **交接锚点与计划表互校**：交接段首行写「下一步：T1.1.1」（计划表里有）→ `devlog.py check` 0 error；写一个不存在的编号 → `S9` 且 exit 1；首行没有锚点 → `S8`；计划表还有未完成任务却写「下一步：无」→ `S9`（「无」只对最新一篇判：更早的档案写下「无」后又被插任务，不追溯）。
14. **开场简报**：还没有任何档案时跑 `devlog.py brief` → 0 error 且提示「尚无会话档案」；建一档、把 §7 首行写成「下一步：T1.1.1」→ brief 复述该锚点并列出计划未完成任务与收件箱 `确立`/`实施中` 计数；计划全部完成时显示「未完成 0」；跑前跑后 `docs/` 字节不变（只读）。
15. **用户侧落点必填**：把 §2 一行的落点留空或写成 `—` / `待补` → `devlog.py check` 报 `S10` 且 exit 1；写成「§3.1」→ 0 error；刚建出的档案（§2 仍是模板占位）不报 `S10`。
16. **待分诊与开工门禁**：`devlog.py ask "要不要拆任务？" --if "计划里还是一个任务"` → `pending` 能看到 `Q1`；此时 `new` 退出码 1 并列出 `Q1`；`pending --clear Q1 --as drop --note "已过期"` 后 `new` 通过；延期 6 条时 `new` 仍拒绝；`brief` 首屏给「待分诊」计数；分诊过的 pending 文件保留（不静默删除）。
17. **跨项目找目录 + 时间线同步**：用开发副本的脚本在**另一个项目目录**跑 `devlog.py new` → 档案建在那个项目里，本仓库会话数不变（`find_docs` 先 cwd 后脚本目录，ISS-028）；`new` 之后 `devlog.py check` 报 `S11`，跑 `devlog.py index` 之后消失（ISS-030）。
18. **转正一步 + 新增前查重**：`pending --clear Q1 --as iss` 不给 `--relation` → 先摆候选再 exit 2；`--relation new --type … --impact … --to …` → 自动分配下一个 `ISS-nnn` 并追加收件箱行；`--relation merge:ISS-nnn` → 不新增行、只标「合并入」；`devlog.py inbox --similar "…"` 能按字面找到候选。
19. **需求状态与出处**：需求行状态写成 `做完了` → `[E22]`；状态 `已实现` 但「依据」是 `—` → `[E23]`；改成 `已实现` + `ADR-001` → 0 error；骨架里 `待实现` + `—` 不报（E22/E23 只要求"声称实现了就指得出出处"）。
20. **功能台账**：功能行状态写 `做完了` → `[E24]`；`满足的需求` 引用不存在的 `REQ-999` → `[E24]`；`已验收` 但代码入口写 `—` → `[E24]`；入口存在 + `verify` + 证据 → 0 error；骨架里 `待评审` 那一行不报。
21. **评审门**：功能行状态推到 `已评审` 但「评审」列是 `—` → `[E24]`；写上三问结论（满足✓ 可做✓ 代价S）→ 不报；历史行（`—（历史）`）带历史评审 → 不报；**挂需求的行拿 `—（历史）` 背书** → `[E24]`。

22. **功能对照的取数**：`devlog.py features` 列出功能台账各行（含 `--state` 筛选）；筛到 `实施中` 时提示对照清单 `40-运行/功能对照.md`（`doc_init` 铺出来的实例）；对照结论只有 `一致 / 差异 / 未覆盖`，写差异必须同时登记一条 ISS。
23. **对账**：需求没有任何功能覆盖 → `W8` 提醒（不阻断：需求可以先写）；功能证据里写「第 99 组」而自测里没有 → `[E26]`；写真实组号 → 0 error。

24. **对齐门**：需求「已实现」但「确认」是 `—` → `[E23]`；写成 `复述✓ 2026-11-01｜档案 012 §2` → 0 error；存量行 `—（历史）` 放行。
25. **考核门与回滚锚点**：`已验收` 的考核写「看着还行」→ `[E27]`；四格齐但缺「完成于」→ `[E27]`；四格 + commit 短号 → 0 error；`撤回` 是合法状态、入口可为空但要写考核。
26. **决策回顾的机器判**：最新一篇 §4 的用户决策块缺「依据」或「撤销条件」→ `devlog.py check` 报 `S12` 且 exit 1；补上是 0 error；写「拍板：agent 自选」可豁免；更早的档案不追溯。
27. **计划表被截断**：在 §5 任务表中间插一个空行 → `plan.py check` 报 `[P13]` 且 exit 1；接回同一张表 → 0 error；一行写成两行（断行）同样报。
28. **YAML 校验器随包走**：`SKILL.md` 的 plain 值含「: 」、引号未闭合，或 `.skill-metadata.yaml` 缩进坏掉 → `build.py` 体检与随包 `self_test.py` 都报；真实的两份文件通过。

29. **问题状态机**：性质 / 状态不在白名单 → `[D3]`；开放问题标 `实现关闭` → `[D5]`；`实施中` 缺关联任务 → `[D6]`；依据没有状态前缀 → `[D4]`；拒绝缺理由 / 重新考虑条件 → `[D7]`；闭环缺闭环日 → `[D8]`。
30. **产出对账**：最新一篇 §6「本次产出」里用反引号列了一个不存在的路径 → `devlog.py check` 出 `[W11]`（提醒，不阻断）；路径都在 → 无 `[W11]`。

31. **任务双亲与考核下沉**：任务写不存在的 `F-999` → `[P14]`；未完成的任务写 `—（历史）` → `[P14]`；删掉功能台账 → `[P14]`（不能当成"没有功能"静默通过）；`已完成` 但「任务考核」表里没有它、或四格 / 完成于缺项 → `[P15]`；任务考核表里有计划里没有的任务 → `[P15]`；功能 `已验收` 却没有任何任务挂它，或汇总点名了不挂本功能的任务 → `[P16]`；汇总不写「各任务考核见」→ `[E27]`。

32. **方向卡**：计划里有 `D1` 而卡里没有 → `[P18]`；卡的「现状 / 成功状态 / 走通验收 / 接缝」任一为空 → `[P18]` 指名那一格；走通验收缺 `@复核日` → `[P18]`；路径 / 接缝 / 走通验收里引用不存在的 `F-nnn` / `W<n.m>` / `K<n>` → `[P18]`（REQ-018 / ISS-061）；卡里有 `D9` 而计划没有 → `[P18]` 孤儿方向；删掉方向卡 → 一条 `[P18]`（不逐行刷屏）；骨架自带的示例行 → 0 error。

33. **设计卡**：工作停在「待开工」却没有卡 → `[P19]`；卡的「接口 / 可替换点 / 失败边界」任一为空或只写「无」→ `[P19]` 指名那一格；卡里写 `W9.9` 而计划 §4 没有 → `[P19]` 孤儿卡；一个工作两张卡 → `[P19]`；删掉设计卡 → 一条 `[P19]`（不逐行刷屏）；已做完的工作不追溯；骨架自带的示例卡 → 0 error。

34. **计划树视图**：`plan.py tree` 列出 方向 / 工作 / 任务 三层，每行带功能、状态、完成于；`--html` 是**单文件**（不引外部资源、页面里写明「不要手改」、离线可看）；`--json` 的 `tasks` 计数与计划表行数一致。

35. **表格竖线**：把 `| ID | 状态 |` 直接写进一格 → `[E28]` 并指出「第 N 行有 9 格、表头 7 格」；写成 `\| ID \| 状态 \|` → 0 error（切表与校验同口径）；数据行以 `|` 开头却不以 `|` 结尾（表尾截断）→ `[E28]` 报「第 N 行表尾截断」，补上末尾竖线即消。

36. **摩擦留痕与转正列**：会话档案模板缺 `### 3.6 本轮摩擦` → 自测第 41 组失败；`pending --clear --as iss` 转正时 `--impact` 落进「影响（不处理会怎样）」列（不是「—」）→ 通过；落进别的列 → 失败。

37. **状态转写子命令**：`plan.py set-status <T-id> --to 已完成 --commit <短号> --review "做法=…｜一致=…｜代价=…｜结论=…"` 一次写全计划 §5 的状态与 FEATURES 的考核行；任务号不存在 / 状态不在白名单 / 锚点写「待提交」/ 缺四格 → exit 1 且两个文件哈希不变；`--dry-run` 只打印清单；原样重跑 → 无改动、不新增任何文件。

38. **已验收 → 对照行**：FEATURES 里 `已验收` 且不在存量豁免清单（F-001–F-020）的功能，`40-运行/功能对照.md` 没有它的行 → `W9` 提醒（不阻断，exit 0）；文案含「有行 ≠ 对照过」；补行或写明为什么不需要后消失；F-001–F-020 与「—（历史）」不报。

39. **设计卡选项空间**：待开工 / 进行中工作的设计卡缺「选项空间」表 / 少于 3 个方案 / 没有「不做 / 少做」/ 被否方案没有回到条件 → `W10` 提醒（不阻断，exit 0）；合法卡不报；`W10` 只判形状，广度够不够仍人读。

40. **五件套批量入口**：`plan.py new-feature` 一次建 `REQ` / `F` / `W` / `T` / `K`；自动编号只认表格首列（正文写 `F-999` 反例不会把下一个推成 `F-1000`）；功能行落在「任务考核」表之前；缺必填 / 撞号 / 分值越界 / 工作与方向不一致 → exit 1 且所有被写文件哈希不变（新工作 4 个 / 挂已有工作 3 个）；`--dry-run` 零写入；`--work-id W1.1` 不新建卡。

43. **3.8 语法门**：随包 `scripts/*.py` 全部能被 Python 3.8 接受——`ast.parse(feature_version=(3, 8))` 拦语句级新语法，另扫 f-string 表达式里的反斜杠（PEP 701 只在 3.12 放开，3.12 的 `feature_version` 不拦）；失败给 file:line；反例（`f"{re.sub(r'\d', '', x)}"`）判出、反证（正则挪出表达式）通过；自测第 65 组。
