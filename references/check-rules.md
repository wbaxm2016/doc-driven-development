# 校验规则：机器能判的，绝不靠人记

三份脚本各管一段，码不重叠：

| 脚本 | 管什么 | 码段 |
|---|---|---|
| `doc_check.py` | 全库形式一致性 | `E*` 阻断 / `W*` 提醒 |
| `devlog.py check` | 会话档案与问题收件箱 | `D*` 收件箱 / `S*` 档案 |
| `plan.py check` | 计划编号、分值、状态词 | `P*` |

**下面每个码都在代码里存在，代码里没有的码不许写进本表。**（旧版曾出现「文档列了 W4/W5 但代码没实现」——那比没有规则更坏：它让人误以为已经守住了。）

---

## doc_check.py

### 错误（阻断，exit 1）

| 码 | 规则 | 常见原因 |
|---|---|---|
| E1 | 缺 front-matter | 新建文件忘加 `---` 块 |
| E2 | 缺必填字段 | `title/layer/domain/status/authority/updated/summary` 少一个 |
| E3 | 枚举越界或位置错 | `layer` 不在 `_schema.json`、`status`/`authority`/`domain` 越界、文件所在目录与 `layer` 不符 |
| E4 | `title` ≠ 正文 H1 | 从模板复制后忘改其一（最常犯） |
| E5 | `summary` 空或 > 80 字 | 把正文当摘要写 |
| E6 | `updated` 非法或未来日期 | 手填错年份 |
| E7 | 相对链接断链 | 文件移动后路径没改；**代码围栏内的链接不检查** |
| E8 | `superseded` 缺 `superseded_by` | 只改了状态没标取代者 |
| E9 | 某层为空 | 建了层没内容：加一篇，或从 `_schema.json` 删层 |
| E10 | ADR 文件名/H1/六段不符 | 文件名不是 `ADR-<三位>-…`；H1 不以 `ADR-` 开头；缺段或顺序错（`## 附录` 豁免） |
| E11 | ADR 索引与 `adr/` 目录不双向一致 | 新增 ADR 未登记索引；或索引指向已删除的 ADR |
| E12 | ADR 编号重复 | 复制粘贴没改号 |
| E13 | 契约层缺「必须」或「不得/不许」 | 把契约写成了说明文，失去约束力 |
| E14 | 文件名含空格或带版本号 | 用 `-v2`、`_final` 表示版本（版本走 front-matter 或 Git） |
| E15 | 取代链断裂 | `superseded_by`/`supersedes` 指向不存在的 ADR；或取代链停在一个自己也 superseded 的 ADR 上 |
| E16 | 出现未登记的术语旧称 | `50-术语/别名表.md` 登记了禁用别名，别处仍在用 |
| E17 | 超出棘轮基线 | 存量问题数比基线多（只在 `--baseline` 下生效） |

### 提醒（不阻断，收尾前应清零）

| 码 | 规则 |
|---|---|
| W1 | `status: active`，但正文首段自述「草案 / 待评审 / 规划中 / 未实现」 |
| W2 | 两份文档 `summary` 完全相同（"两处在说同一件事"的唯一机器信号） |
| W3 | 段内是占位 `原文未记录`（待补） |
| W4 | `superseded_by` 是 `待补/未标注` 之类的占位，不是 ADR 编号 |
| W5 | 引用块里的「补记」缺 `补记于 YYYY-MM-DD` 日期戳 |
| W6 | 用了绝对路径链接（换目录就断） |
| W7 | 带 `REQ-nnn` 的条款行没有任何规范措辞（`WHEN/IF/WHILE/GIVEN/SHALL/当/若/一旦/必须/应/不得/不许`）——大概率是个名词短语，不是可判真假的需求 |

## devlog.py check

| 码 | 规则 | 级别 |
|---|---|---|
| D1 | `ISS-nnn` 编号重复（`done` 条目留在主表 + 已闭环表 → 必报） | 错误 |
| D2 | 收件箱 `deferred` 条目缺「回到条件」 | 错误 |
| S1 | 会话档案缺 front-matter 或 `title/session_date/session_no/scope` | 错误 |
| S2 | `title` 与 H1 不一致 | 错误 |
| S3 | `session_date` 不是 `YYYY-MM-DD` | 错误 |
| S4 | 七段缺失或顺序不符 | 错误 |
| S5 | 引用了收件箱里不存在的 `ISS-nnn` | 错误 |
| S6 | 交接段过短（去掉标记后 < 40 字） | 提醒 |
| S7 | 文件名前缀不是 `<session_date>-<session_no>-` | 错误 |

## plan.py check

| 码 | 规则 |
|---|---|
| P1 | 任务编号不合规（应形如 `T1.1.1`） |
| P2 | 任务编号重复（含已完成任务，全量扫描） |
| P3 | 状态词不在 `_schema.json` 的 `plan.states` 白名单里 |
| P4 | 分值不是 1–5 的整数 |
| P5 | 「所属」的工作不存在于「工作」表 |
| P6 | 任务编号前缀与所属工作不一致（`T9.9.9` 挂 `W1.1`） |
| P7 | 权重行含非数字，或某视角权重全为 0 |
| P8 | 有未完成任务，但所有视角都排不出可做的（全被前置卡死） |
| P9 | 工作编号 / 方向编号不合规 |
| P10 | 表格行列数不符（少了个 `\|` 或多了个单元格） |
| P11 | 「前置」指向表里不存在的任务编号 |
| P12 | 「工作」的方向列指向方向表里不存在的编号 |

`plan.py` 的错误同样带码打印（`ERROR [P11] ...`），可以直接 grep，与 `doc_check.py` / `devlog.py` 一致。

> P11/P12 存在的原因：引用不存在的编号时，那个任务会被永久标 ⛔（或让读者以为方向还在），
> 而分数与排序看起来一切正常——这是最难自己发现、也最贵的一类静默失效。

## 为什么这几条必须是机器判

- **E4**：`title` 与 H1 不一致，会导致索引显示一个名字、读者看到另一个名字。
- **E7**：断链是文档体系最常见的腐烂方式，且肉眼几乎发现不了（引对了文件、引错小节照样"看起来没问题"）。
- **E11/E12/E15**：一旦索引与目录不一致、"哪个决策还有效"就失去唯一入口；取代链断了，成因追溯就断了。
- **E13**：没有「必须/不得」的契约层会退化成解释文——它会一直"通过评审"，直到某次实现跑偏才被发现。
- **P6**：编号本身就是结构信息（`T1.1.1` 属于 `W1.1` 属于 `D1`），乱掉的编号让"这个任务服务于哪个方向"无法机器推导。
- **W2**：这是「一个事实一处」的**唯一机器信号**——两份 summary 一样，通常意味职责没收敛。

## 修完全绿之后，剩下什么仍需人读

别把全绿读成零债务：

- 条款**写得对不对**（E13 只判「必须」二字在不在，判不了后面那句话是否可判真假；W7 只是弱信号）。
- 交叉引用的**语义正确性**（只判路径存在，不判「引对了没有」）。
- 两份文档是否在**语义上**说同一件事（只靠 W2 的 summary 相同这一条弱信号）。
- ADR 的撤销条件**是否已经成立**——需要定期人工复核，脚本不会主动提醒。
- 决策依据**是否真的支持**该决策。
- 外部链接是否失效——交给 `lychee`（见 `references/ecosystem.md`），不塞进收尾流程。

## 收尾命令

```bash
python scripts/doc_check.py            # 0 error
python scripts/doc_check.py --quiet    # 只打印汇总
python scripts/doc_check.py --json     # 给 CI / 看板用
python scripts/doc_check.py --baseline # 棘轮：存量债只许降
python scripts/devlog.py check
python scripts/plan.py check
python scripts/devlog.py index --check && python scripts/plan.py index --check   # 生成区幂等
```
