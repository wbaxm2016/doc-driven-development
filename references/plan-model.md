# 计划模型：三层 + 六维 + 三视角

## 为什么需要它

只有过程档案时，你能回答"之前发生了什么"，但回答不了"接下来做什么、为什么是它"。
散落的"重要性：中偏高"这类形容词**无法比较任意两项**，等于没有排序。

## 三层（唯一分层判据）

判据：**会话收尾时能不能一句话说清"这个做完了"**。

| 层 | 编号 | 粒度 | 完成判据 | 生命 |
|---|---|---|---|---|
| 方向 | `D-n` | 1–3 个月，**3–5 个** | 一个能被复述的成功状态（不是任务列表） | 季度 |
| 工作 | `W-n.m` | 1–3 场会话 | 一条命令 / 一次实测 / 一份文档落地 | 周 |
| 任务 | `T-n.m.k` | 一场会话内勾掉 | 产物存在且证据可贴 | 天 |

- 说不清"做完了" → 它是**工作**，不是任务。
- 说得清但说不清"为什么值得做" → 它是**方向**，不是工作。
- **默认不设第四层**：空层是最典型的文档债。某方向工作 >15 才拆子方向，且先写 ADR。
- 编号前缀是**结构**，会被 P6 校验：`T1.2.3` 的「所属」必须是 `W1.2`。

## 状态词表（唯一来源：`_schema.json` 的 `plan.states`）

| 状态 | 含义 | 参与排序 |
|---|---|---|
| `待开工` | 还没动手 | ✅ |
| `进行中` | 本次会话正在做 | ✅ |
| `已实现（未验收）` | 代码在，但门禁/判据没过 | ✅（**不等于完成**） |
| `已完成` | 门禁或判据已过，有证据 | ❌ 不排 |
| `阻塞` | 在等外部条件 | ✅（但通常被前置卡住） |
| `搁置` | 主动不做，等回到条件 | ✅ |

**写不在表里的词，`plan.py check` 会直接报 P3。** 这是刻意的：旧版只认硬编码的「已完成」，写「完成」的任务会被静默当成未完成继续参与排序——比报错难查得多。

要加状态词，改 `_schema.json` 的 `plan.states` 与 `done_states` 两处（同一文件），不要改代码。

## 六维（统一方向：分越高越该先做；成本取反）

| 代号 | 维度 | 5 分含义 |
|---|---|---|
| `U` | 用户可感知 | 用户当场能看见或用上 |
| `C` | 闭环贡献 | 直接补齐某个门禁/闭环缺口 |
| `S` | 系统完备 | 补的是能力空洞，不是打磨 |
| `R` | 正确性风险 | 会产出错的数或静默失效 |
| `V` | 可验证 | 做完立刻能判真假 |
| `E` | 实施成本（取反） | 半场会话以内 |

## 三视角（= 三行权重；加视角只是加一行）

| 视角 | U | C | S | R | V | E |
|---|---|---|---|---|---|---|
| 尽快看到效果 | 5 | 4 | 2 | 3 | 2 | 2 |
| 系统更完备 | 2 | 4 | 5 | 3 | 3 | 2 |
| 核心功能优化 | 2 | 2 | 3 | 5 | 4 | 2 |

计分：`score = Σ(权重×分值) / Σ权重`，保留两位；**只在同层内比较**。

## 三条硬约束（优先于分数）

1. **门禁 > 优先级**：门禁未全绿，后续阶段只许做设计，不许实施。
2. **一票置顶**：`R=5` 且改动已存数据/已生效契约 → 不看分数直接置顶。
3. **前置未解不排期**：排序视图里标 `⛔`，不进 Top。

> 这三条存在的理由：不让"分数"变成绕过门禁的借口。
> 注意：1 和 2 是**人**的约束，脚本不判——脚本只保证 3（`⛔`）与分数算得对。

## 操作

```bash
python scripts/plan.py check            # P1–P10：编号 / 分值 / 状态词 / 所属工作
python scripts/plan.py check --json     # 给 CI 用
python scripts/plan.py index            # 重算各视角排序视图，写回文档生成区
python scripts/plan.py index --check    # 只比对，CI 用
```

脚本按**表头**识别维度列（单个大写字母列即维度），因此：加维度＝加列+加权重，加视角＝加一行，**都不改脚本**。

## 状态词纪律

`已实现（未验收）` ≠ `已完成`。前者只是代码在，后者要门禁/判据过。
状态只允许被**证据**推进：实测输出、ADR、测试通过。禁止"感觉做完了"。

## 演进原则

1. 加维度只加列，不改机制（例：出现"错过窗口就失效"的任务时加 `时敏性`）。
2. 加视角只加权重行。
3. 拆第四层需 ADR + 触发条件（工作数 >15）。
4. 本文件 >200 行才按方向拆片。
5. **一旦出现两份都在定义"下一步"，删掉弱的那份**，不做两边同步维护。
