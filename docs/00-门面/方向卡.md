# 方向卡

> **方向是现状的结论，不是独立的一步。** 先 `brief` 读一屏，再多轮对话把「现在有什么、卡在哪、哪些是旧账、哪些是新问题」说清楚，再把结论写成这张卡；卡没写出来，不要往计划 §3 加 `D`。
>
> **一个方向一行，内容只写在这里。** 计划 §3 只登记 `编号 / 方向 / 卡 / 依据`；同一件事不要在两张表里各写一份（硬规则 1）。
>
> **接缝是分水岭，但它写的是「步与步之间」，不是「模块内部」**：上一步的输出 / 失败 / 权限 / 空状态怎么影响下一步。模块内的异常处理归设计卡的「失败边界」（`P19`）——写反了，方向线就退化成一张多余的纸（ISS-069）。
>
> **走通验收不是一条 `verify:` 命令。** 它是在干净环境里按路径走一遍，每步记录观察结果（含失败路径、空状态、权限、重试）。`P18` 判四格在不在（现状 / 成功状态 / 走通验收 / 接缝）、走通验收带 `@YYYY-MM-DD` 复核日、路径 / 接缝 / 走通验收里出现的 `F-nnn` / `W<n.m>` / `K<n>` 引用存在；走没走通、接缝归谁仍由人判（REQ-018）。

> **复核日期**：走通验收里写 `@YYYY-MM-DD`（下次该复核的那天）。到期后 `devlog.py brief` 会单列「复核：已到期 N」——这是 ADR-003 撤销条件 4（连续 3 个月无走通记录）能判得动的前提（ISS-048 / ISS-050）。

> **「现状」是判断，不是报表。** 写「有什么 / 卡在哪」这类不易过期的判断；必须写计数时带日期（`2026-11-03 核实`），否则三个月后它就是一句假话（ISS-064）。

## 链路

> **覆盖看「本步走过没有」，链路看「步与步之间串起来没有」。** 覆盖表数的是单条方向线；这张表数的是跨组件的串联——上一步的输出进下一步、失败后谁回填、空状态与权限怎么传。
>
> **一条链路至少串起 2 个功能点（`F`）。** 只在一个功能点内部的流程不算链路；方向（`D`）只作归属、不作门槛。
>
> **`P20` 只判形式**（ADR-006）：五格在不在、`F` 是不是真的、走通验收带 `@YYYY-MM-DD`、引用的 `F` / `W` / `K` 存在。走没走通、接缝归谁仍人判；`brief` 用它算 `链路覆盖 n/m`。
