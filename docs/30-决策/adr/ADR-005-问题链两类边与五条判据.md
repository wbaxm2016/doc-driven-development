# ADR-005 · 问题链：两类边与五条判据（根因未关，表象只停在确立）

> 一文件一决策。命名 `ADR-<三位编号>-<短标题>.md`；编号只增不复用。
> **双向链**：本决策取代别人，写在 `supersedes`；被别人取代，写在 `superseded_by`。
> 两条链都会被 `doc_check.py` 的 E15 校验：指向的 ADR 必须存在，且取代链必须终止在一个活决策上。

## 状态

active（2026-11-08 起）。决策来自用户 2026-11-08 对选项 C 的选择与复述门的三点确认（① 引自与「谁先修」两者都记 ② 根因未关时表象不能关闭 ③ 标记给机器判）。本 ADR **补充** ADR-003 的问题模型，不取代它。

## 背景

四个事实把「问题链」这件事推到了台面上：

1. **问题会引出更底层的问题。** 修表象时发现根因，根因不修，表象修了也是白修——这是开发的常态，不是例外。今天就有两条：ISS-102（包里的 `plan.py` 坏了）的真正根因是「修复的定义没包含重打 `dist/`」；ISS-101（3.8 无判据）做到一半发现 `feature_version` 是假门，于是逼出 ISS-103。
2. **现有模型没有「关系」这一维。** ADR-003 的四维是层 / 状态 / 性质 / 类型，全是单行属性；链只能写在「落点」「依据」的自由文本里。
3. **链其实已经存在，只是判不了。** 收件箱 103 行里有 14 行正文提及其它 ISS；`devlog.py` 的 `S5` 只判「会话档案里提到的 ISS 存在」，**对收件箱内互相引用一个字都不判**，更分不清「引自 / 必须先修 / 只是提及」。
4. **DSH 记得的只是会话上下文。** 它会话内能复盘这条链（`session_review` 可读），但不进项目台账；换会话或压缩之后，链就只剩自由文本。技能要的是台账里可判的链。

## 决策

### 1. 两类边，落在「落点」列，不新增列

固定写法（与代码里的正则同口径）：

| 写法 | 含义 | 方向 | 判什么 |
|---|---|---|---|
| `源自 ISS-nnn` | 这条是在处理 / 看到 `ISS-nnn` 时发现的 | 历史 | 引用存在、不自指、时间不倒挂 |
| `须先 ISS-nnn` | `ISS-nnn` 不修完，这条不能推进 | 排期 | 引用存在、不自指、无环、被挡住时只能「确立」 |

**不新增列**：新增列会让收件箱 103 行全部错位（`E28`），迁移成本大于收益。旧行**不追溯**（棘轮），只对写了标记的行生效。

### 2. 五条判据（机器判形状，人判归属）

| 码 | 判什么 | 级别 | 为什么 |
|---|---|---|---|
| `D11` | 两类边指向的 `ISS` 必须存在，且不能指向自己 | error | 指向不存在的编号 = 链断了却没人知道 |
| `D12` | `须先` 图无环 | error | A 须先 B、B 须先 A 是排期矛盾 |
| `D13` | 被**未关闭**的 `须先` 挡住时，本行状态只能是「确立」（不得「实施中」，也不得「实现关闭」） | error | 这正是「根因未关，表象不许关」；同时禁掉并行推进 |
| `D14` | `源自` 的来源行发现日不得晚于本行 | error | 时间倒挂说明编号写错或日期填错 |
| `W13` | `须先` 指向的行已闭环 → 提醒本行可推进 | warn | 链的**唤醒**：根因修完，表象不该继续躺着 |

### 3. 排期规则

发现更底层的问题时：**先修根因；表象停在「确立」，不许并行「实施中」。** 这条不只写在文档里——`D13` 让它可判。表现层收口时若根因还开着，`D13` 会红。

### 4. 不判什么

不判「这条到底是不是根因」，也不判「这个 `须先` 判断对不对」——那是人的判断。机器只判形状与状态一致性。

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| 不做（现状） | 链只活在自由文本里；收口时先修表象——ISS-102 差点在 002 就宣布闭环 |
| 只写规则（B） | 没有机器判据；「规则靠自觉必然失效」是本项目反复验证过的事 |
| 一等模型（D：新列 / 问题树文档 / `brief` 出链） | 迁移 103 行；且「要链视图」还没有证据（没人问过「这条从哪来」≥ 3 次）。等证据再升级 |
| 给 `源自` 也上「必须追到根因」的强判据 | 引自是历史事实，不是承诺；强判会把「顺带发现」变成「必须追根」 |

## 影响

- **新码**：`D11`–`D14`（error）、`W13`（warn），进 `devlog.py` 的码表与 `SKILL.md`；`self_test` 第 66 组断言（正反例）。
- **模板与规则**：`assets/templates/inbox.md`、本仓 `docs/70-过程/问题收件箱.md` 表头规则、`SKILL.md`「问题收件箱」一节各加一段。
- **兼容**：旧行不写标记 → 不判、不报警，`devlog check` 结果不变（棘轮）。
- **与 ADR-003 的关系**：四维不变，新增的是「行与行之间」的边；ADR-003 仍是问题模型的唯一权威，本 ADR 只加关系维。
- **不发散**：`brief` / `next` 暂不显示链；等出现第 3 次「还要先修谁」的追问再考虑（当时记进 ISS）。

## 撤销条件

出现以下任一，回到「只写规则」并作废本 ADR：

- `W13` 在真实使用里从没触发过（说明链写了也不看）；
- 误报：把「顺带提及」判成 `须先`，导致正常的并行推进被反复挡住 ≥ 2 次；
- 出现 ≥ 3 次「`brief` 为什么不出链」的需求（说明该升级成 D，而不是撤销）。
