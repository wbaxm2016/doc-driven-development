# ADR-006 · 全局视角与系统视角：两种读法共用一份事实

> 一文件一决策。命名 `ADR-<三位编号>-<短标题>.md`；编号只增不复用。
> **双向链**：本决策取代别人，写在 `supersedes`；被别人取代，写在 `superseded_by`。
> 两条链都会被 `doc_check.py` 的 E15 校验：指向的 ADR 必须存在，且取代链必须终止在一个活决策上。

## 状态

active（2026-11-08 起）。用户提问「该技能需要全局视角，还需要系统视角。这两者的关系怎么安排？」，随后以「按你推荐」采纳方案 B。拍板与逐项对比见 `2026-11-08-006` §4 D1。本 ADR **补充** ADR-003 的计划模型与 REQ-022 的覆盖口径，不取代它们。

## 背景

三个事实把「两个视角」推到台面上：

1. **覆盖只证「每步走过」，不证「串起来走过」。** 方向卡的 `覆盖 n/m` 是每条方向线各走一次的记录（REQ-022）；它答不出「A 的输出进 B、B 失败后 A 怎么回填」这类跨环节的问题。
2. **组件级证据已有，串联级没有。** 五连跑、建档→校验→回写、发版→装机都是「上一步写、下一步读」的串联，失败一过只剩人记得（D13 的现状）。
3. **两个视角会互相打断。** 全局要求收敛到「下一步做什么」，系统要求发散看「所有边接没接上」；同一次回答里做两件事，两边都做不实。

## 决策

### 1. 两个视角都要，但只有一份事实

- **全局视角**＝层次与顺序的投影：方向 → 工作 → 任务、需求 → 功能 → 任务、「下一步做什么」。载体已有：开发计划、方向卡、`brief`。
- **系统视角**＝边与接缝的投影：哪些环节串起来、接缝在哪、验过没有。载体是方向卡的「链路」表，每条记录只写 `D` / `W` / `F` / `K` 的引用，不新建台账。
- **判据**：链路行必须引用 ≥2 个功能台账里真实存在的 `F`（方向只作归属、不作门槛——一个方向内跨组件恰恰最容易断）；出现「只服务某一个视角的第二份表」即违约。

### 2. 拆成三条需求，分散在三个面

| 编号 | 面 | 一句话 |
|---|---|---|
| REQ-039 | 载体 | 跨 ≥2 个方向的链路在方向卡各占一行，写清起终点、跨方向、接缝、走通验收、记录 |
| REQ-040 | 校验 | `plan.py check` 只判链路形式（跨 ≥2 方向、接缝非空、`@复核日`、引用存在、有日期就有结论与证据） |
| REQ-041 | 简报 | `brief` 同时给 `覆盖 n/m`（全局）与 `链路覆盖 n/m`（系统）+ 未验接缝清单；缺表不报错 |

### 3. 机器判形式，人判语义

两条写进 `requirements.md` §2「不得做的事」：不为系统视角新开第二份事实；机器不判「走没走通」「先补哪条」。

### 4. 人机分工：实现层归 AI，系统级理解与目标归人

开发产品在「还没做出来」时，人无从判断怎么调才对；这时把实现决策交给 AI，人守两件事——**系统级理解**（这套东西怎么串、换一处会影响哪几处）与**要实现的目标**。项目哲学是快速开发、保持可修改可替换可扩展，因此默认选择是「能改、能换、能扩」，而不是「一次选对」。

这条分工把技能**定位**推向「不懂开发或经验不足的开发者也能用」：他们不需要判断实现细节，只需要守住系统级理解与目标。代价是「哪些由 AI 定、哪些必须人核」必须写清，否则新手会把 AI 的实现决策当成验收结论——这一条已登记 ISS-104，待后续单开方向补边界与实现核对。

### 5. 使用时序分开

开场用全局视角（`brief` 一屏收敛到下一步）；收尾用系统视角（这一轮改了什么、串起来断没断）。不是分人，是分时。

## 备选方案

| 方案 | 为什么不选 | 回到条件（出现即重新比较，增量更新本表） |
|---|---|---|
| A 合成一张图 | 两种读法挤一屏，收敛与发散互相打断 | 链路表与计划树长期没人分别读、合并后反而更常用时 |
| C 两 Owner、两份载体 | 同一事实两处定义，产生同步债（违反硬规则 1） | 系统视角需要独立生命周期、且无法用编号引用时 |
| D 全局为主、系统按需 | 缺口不进台账，等于回到「失败一过只剩人记得」 | 跨方向改动频率降到很低、临时拉图已够用时 |
| E 不做系统视角 | 系统级覆盖无从验收，目标落空 | 目标改回「每条线走过即算覆盖」时 |

## 影响

- **新码**：`P20`（`plan.py check` 的链路形式判据），进码表与 `SKILL.md`。
- **模板**：`assets/templates/direction.md` 加「链路」小节；本仓 `docs/00-门面/方向卡.md` 同步并补真实链路行。
- **脚本**：`devlog.py brief` 增「链路覆盖」与「未验接缝」两行；`--json` 同步。
- **断言**：`self_test` 第 67 组（正反例），随包走。
- **需求**：REQ-039 / REQ-040 / REQ-041；F / W / T 在实现时拆。
- **不发散**：不自动跑业务路径、不绘系统图、不判接缝归属、不动其它技术债。

## 撤销条件

出现以下任一，作废本 ADR 并回到 A / D 比较表：

- 同一事实被迫维护两份（第二张表出现）；
- 链路行连续 3 场为空，或 `brief` 的两行从没人看过 / 问过；
- 误报：合法链路因「串起 ≥2 个 `F`」被反复判红 ≥ 2 次（说明该放宽为「跨 ≥2 个功能点或工作」）；
- 人开始把「脚本绿」当成「走通」（`P20` 只判形式，出现这种依赖即越界）。
