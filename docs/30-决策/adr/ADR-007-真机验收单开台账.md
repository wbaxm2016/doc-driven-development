# ADR-007 · 真机验收单开台账：等用够或攒够再定

> 一文件一决策。命名 `ADR-<三位编号>-<短标题>.md`；编号只增不复用。
> **双向链**：本决策取代别人，写在 `supersedes`；被别人取代，写在 `superseded_by`。

## 状态

active（2026-11-08 起）。用户提「扩展，要新建一类问题存放，就是需要真机验收的问题；有些需要长时间使用，有些需要足够多数据支撑才能决定后续方向」，随后逐轮拍板：载体「单开验收表」、记录「观察记录子表」、状态「三态」、出口「三档枚举 + 必须带编号」、编号「RV」、样本型按「不同场景数」计、记录「AI 每场问一句 + 自动从会话捞」。拍板过程见 `2026-11-08-010` §4。

## 背景

1. **现状缺落点。** REQ-044 要求「两种实现比不出优劣时保持可替换，并登记一条待真机验证问题」，但这类问题既不是缺陷也不是待办：修完就关的寿命模型套不上它，收件箱里只能塞一句「回到条件 @日期」，数据型连日期都没有。
2. **两类判据需要的字段不同。** 「用够久」有日历锚点，「攒够数据」没有——次数得有人累计，否则「攒够 20 次」永远停在 0。同一个人在同一场景用十次，不算十份数据。
3. **结论没有出口。** 观察结束后可能是「保持、转正」「要改、开新任务」「撤销、回滚」三种结局；只留一个「已定论」会让人分不清是批准还是否决。

## 决策

### 1. 单开一张台账，RV 编号只增不复用

载体是 `70-过程/真机验收台账.md`，与问题收件箱并列。主表九列：`ID / 开单日 / 观察对象 / 判据 / 为什么现在定不了 / 状态 / 结论 · 出口 / 回看日 / 更新`。不并入收件箱，也不挂在设计卡上随工作归档。

### 2. 判据三型 + 观察记录子表

判据写 `类型:门槛`：`时长:N`、`场景:N`、`信号:一句话`。每次使用在子表追加一行（日期 / 场景 / 观察到什么 / 本次增量 / 记录人），**进度由子表累加，不设手写进度列**——避免「数字说 12 次、记录只有 5 条」。样本型按不同场景数计。

### 3. 三态与三档出口

状态：观察中 → 信号已足待拍板 → 已定论。中间态单独存在，是因为「数据够了但没人拍板」最容易静默躺着。出口三档：`保持：一句话`、`改造：T 或 REQ 编号`、`撤销：回滚 <commit 短号>`；改造与撤销必须能落地。

### 4. 记录走「AI 问一句 + 自动捞」

每场收尾 AI 问一句「这段时间用到了吗」；会话里出现「刚试了…」这类痕迹时直接追加，记录人标 AI 或用户。只靠人记会烂尾，只靠自动捞会漏掉「没说但该记」的。

### 5. 不主动弹

这张表不进开场简报、不显示计数；用户问「还有哪些问题」时才展开（`rv list`）。

### 6. 触发面扩到「非最终版实现」

REQ-044 原本只覆盖「两种实现比不出优劣」；现扩为：比不出优劣、明知是临时方案、结论依赖真机体验。纯实现选择、行为不变的重构、能当场验证的，不开单。

### 7. 机器只判形式

`devlog.py check` 新增 V1–V6：编号格式与重复、判据格式、状态词、定论出口是否带编号（T 须在计划 §5、REQ 须在契约）、观察记录是否指向存在的编号且日期合法、回看日格式。判不了「用够了没有」「这个场景算不算新」。

## 备选方案

| 方案 | 为什么不选 | 回到条件（出现即重新比较，增量更新本表） |
|---|---|---|
| A 收件箱加一个类型 | 寿命模型不同：修完就关 vs 等到有结论；数据型没有日历锚点 | 这类条目长期不超过三五条、且从不需回看进度时 |
| B 普通问题存事实 + 生成待观察视图 | 事实只有一处，但「攒够样本」仍需子表计数，视图解决不了计数 | 计数需求消失、只看「到没到日子」时 |
| C 挂在设计卡上随工作归档 | 工作一收工就归档，观察期往往长于工作期 | 观察期稳定短于对应工作的收尾周期时 |
| D 少做：只扩大触发面，仍写进收件箱 | 触发面扩大后收件箱会被「还没结论」的条目淹没 | 用户明确接受收件箱变长、且不再问「用够了没有」时 |
| E 自动开单 + 自动改状态 | 机器判不了「这些数据够不够代表」，自动结论会让人误当验收 | 出现可机读的客观判据（报错率、耗时）且不需要人判时 |

## 影响

- **新文件**：`docs/70-过程/真机验收台账.md`；包内模板 `assets/templates/verification.md`，`doc_init` 新建项目时铺出。
- **新码**：V1–V6（`devlog.py check`）。
- **新命令**：`devlog.py rv list / new / add`。
- **配置**：`names.verification`、`ids.verification`、`verification.{types,states,outcomes}`，`assets/default-schema.json` 与 `docs/_schema.json` 同步。
- **契约**：REQ-044 扩触发面；新增 REQ-045。
- **断言**：`self_test` 第 69 组（正反例）。
- **不发散**：不自动改状态、不主动提醒、不并入收件箱、不判场景是否算新。

## 撤销条件

出现以下任一，作废本 ADR 并回到 A / D 比较表：

- 台账连续 3 个月零新增，且没人问起；
- 观察记录长期为空（记一行都嫌烦），丙的价值被证伪；
- 「改造」出口连续 3 次指向无效编号、每次都靠人补救；
- 用户开始把「脚本绿」当成「验收通过」（V 码只判形式，出现这种依赖即越界）。
