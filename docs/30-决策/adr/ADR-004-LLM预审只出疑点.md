# ADR-004 · LLM 预审：只出疑点与逐字证据，判定权不变

> 一文件一决策。命名 `ADR-<三位编号>-<短标题>.md`；编号只增不复用。
> **双向链**：本决策取代别人，写在 `supersedes`；被别人取代，写在 `superseded_by`。
> 两条链都会被 `doc_check.py` 的 E15 校验：指向的 ADR 必须存在，且取代链必须终止在一个活决策上。

## 状态

active（2026-11-04）。用户先确认方向「要做，确定是预审」，后明确「不复述，按建议落」——按 `decision-restate` 照实记：**放弃复述、按 agent 建议落**，不写成「用户确认过」。

## 背景

1. **语义判断今天全靠人。** README 写「机器判形式 / 人判语义」：评审门三问、设计门的可替换点、对照门的「做的是不是这一句」、考核门的「值不值」，机器只判字段在不在。
2. **LLM 能替人把材料摆齐。** 需求原文、对照清单、考核四格、设计卡都在仓库里，模型能读出来并指出「这里对不上、这里没有证据」。这一步不减人的判断，只减人找差异的时间。
3. **这条线已经画过一次。** 2026-11-04-002 选 B（LLM 出建议 + 脚本核引文 + 人裁决），否决 C（LLM 直接写入载体），理由是「模型措辞被当成用户结论，违反对齐门」。
4. **判定权在不变骨架里。** `technical-design.md` §4 把「判定权（谁能改成什么）」列为不变的骨架，改它要 ADR + 版本号。本决策**不改判定权**，只加一个建议通道。
5. **项目目标新增一条**：降低与 AI 协作开发的认知负荷（2026-11-04，用户）。语义门前人要把需求、实现、对照、考核几份文档并排读，这是当前最重的一段负担。

## 决策

1. **预审是建议通道，不是裁决通道。** 输出只含四格：指向（编号 + 文件 + 行）、逐字引文、疑点（一句话）、建议动作（补证据 / 改条款 / 维持）；裁决列初始「待裁决」，只由人填。
2. **不得写入任何台账的 `状态` / `确认` / `评审` / `考核` 列。** 预审记录随会话档案，`authority: 4`，不构成约束。
3. **不预审、只摆材料、不出结论的三处**：对齐门的复述 / 采纳（复述必须是用户自己的话）、发版 / 回滚拍板、开放问题收口。
4. **可预审的四门**：评审门三问的证据面、设计门的接口与失败边界缺口、对照门的「行为 vs 需求原文」、考核门的证据与未解释差异。
5. **每条必须可核对**：引文逐字存在（`E30` 拒收改写）、指向带文件与行；给不出引文就标「未核实」，不得当结论。
6. **试点只做对照门**：选它的标准是「效果最容易看到」——输出是「需求原句 vs 实际行为」的逐字对比，有没有用当场能核；成本低、可回退只是附带，不是理由。

## 备选方案

| 选项 | 说明 | 为什么没选 | 回到条件（什么事实出现就重新考虑） | 触发信号（可观察的） |
|---|---|---|---|---|
| A | 让 LLM 直接判门，给结论并回写状态 | 判定权变更；模型措辞会被当成用户结论，2026-11-04-002 的 C 已因此被否 | 预审与人的裁决连续 20 场逐条一致，且每条都能被独立复核 | 人开始引用「预审说」而不引原文 |
| B | 只做材料汇总，不标疑点 | 人仍要自己找差异，省不下时间；汇总与预审的差别就是「有没有指出不一致」 | 汇总连续 10 场无人读 | 汇总记录从不被引用 |
| C | 预审只在对话里说，不落档 | 不可核对、不可回溯；同一场会话说两遍口径就会漂 | 预审结论开始跨会话口口相传 | 出现「上次预审不是这么说的」 |
| D | 四道门一次上 | 一次改四处口径，出问题无法归因 | 对照门试点 3 场无误判，且人要加其余门 | 其余门持续没有预审记录 |

- `scripts/self_test.py`：第 49 组（正反例）。

## 撤销条件

出现下列任一可核对事实，就推翻本决策：

1. **噪音大于收益**：连续 10 场预审与人的裁决不一致 ≥ 3 次，停用或收窄成只汇总。
2. **建议通道被当裁决通道**：出现「未读预审、直接按建议改状态」≥ 2 次，收窄或撤销。
3. **没人用**：上线 3 个月内 0 条预审记录，撤销。
4. **成本高于收益**：单场预审要把整篇文档重复喂给模型才成立，收窄到只预审对照门。
