# 代码地图 · 旁注

> **这是人写的唯一来源。** `代码地图.md` 是生成物（`python scripts/codemap.py build` 重算），
> 说明文字全部来自这里；改地图请改这份，不要手改生成物。
>
> 为什么要有这一份：机器能抽出「谁调我 / 我调谁」，抽不出「这个函数为什么存在、出错时停在哪」。
> 后者写在这里，一行一句。
>
> **「干什么」的写法**：写职责，不写代码步骤。写「读文件再解析」等于没写；写
> 「把一份契约增量按锚点合进主表，越界就拒」才算写清。判据是——不看代码的人读完这句，
> 能判断「我该不该动它」。

## 函数旁注

### yaml_rules.py

| 函数 | 干什么 | 从哪进来 | 失败时怎样 | 改它谁被牵连 |
|---|---|---|---|---|
| frontmatter_block | 从一份 Markdown 里取出第一段 `---` 包住的 front-matter 正文 | `doc_check` 与 `self_test` 各自解析被检文件时调用 | 不抛错：没有 front-matter 就返回空串，由调用方把「空」判成「缺 front-matter」再报 | `doc_check` 的全部 front-matter 判据；`self_test` 读档案与计划也走它 |
| frontmatter_problems | 按「严格 YAML 子集」逐行检查 front-matter，返回问题清单；只管能不能被解析，不管内容对不对 | `doc_check` 的 front-matter 判据；`build.py` 体检 `SKILL.md`；`self_test` | 从不抛异常——所有问题收进返回列表，报几条由调用方决定 | 五个宿主的加载都会受它影响：判宽了坏 YAML 会装进宿主并静默丢掉整个技能，判严了会把合法写法误报成错 |
| metadata_problems | 检查 `.skill-metadata.yaml` 的结构：缩进层级、同级键重复、标量形态、块标量 | `build.py` 打包前的体检 | 同上，只返回清单不抛错；块标量只跟缩进，不判断文内容对不对 | 只影响 `.skill-metadata.yaml` 的结论；它与 front-matter 那条链共用 `_KEY` / `_BLOCK`，改共享常量会同时改到两边 |
| _plain | 判一个不带引号的值里有没有会让严格 YAML 解析失败的三样东西（`: `、行尾 `:`、` #`、制表符），命中就写一句人话进调用方给的 add | 只被 `frontmatter_problems` 调用 | 无状态、不抛错；add 是回调，收集到哪由调用方决定 | 只此一处调用，但它和 `_scalar` 判的是同一批字符，两处口径必须一致，否则 front-matter 与 metadata 会给出不同结论 |
| _scalar | 判单个标量的形态：引号是否闭合、plain 值里有没有危险字符、是否以 YAML 保留字符开头 | 只被 `metadata_problems` 调用 | 不抛错；开头是 `{` `[` `&` `*` `!` 或竖线这类 YAML 保留字符的值，会被判成不在子集内 | 只此一处调用，与 `_plain` 口径耦合（见上一行） |
