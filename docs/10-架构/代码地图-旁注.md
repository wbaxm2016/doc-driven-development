# 代码地图 · 旁注

> **这是人写的唯一来源。** `代码地图.md` 是生成物（`python scripts/codemap.py build` 重算），
> 说明文字全部来自这里；改地图请改这份，不要手改生成物。
>
> 为什么要有这一份：机器能抽出「谁调我 / 我调谁」，抽不出「这个函数为什么存在、出错时停在哪」。
> 后者写在这里，一行一句。
>
> **「干什么」的写法**：写职责，不写代码步骤。写「读文件再解析」等于没写；写
> 「把一份契约增量按锚点合进主表，越界就拒」才算写清。判据是——不看代码的人读完这句，
> 能判断「我该不该动它」。

## 入口表

> 机器只认 `add_parser` / `set_defaults` 这类明确形状；**靠兜底 return 派发的**（devlog 的 `index`、
> observe 的 `run`）和**纯开关脚本**（只有 `--quiet` 之类）机器认不出，只能在这里声明。

## 函数旁注

### codemap.py

| 函数 | 干什么 | 从哪进来 | 失败时怎样 | 改它谁被牵连 |
|---|---|---|---|---|
| die | 统一错误出口：印带 ERROR 前缀一行并给退出码，输入缺失有固定口径 | main 在校验目录或解析失败时调 | 不抛不退出，只返回码（默认 2），冒泡到 sys.exit | main 的 build 与 check 失败路径；改码值会改调用方约定 |
| find_docs | 定文档目录：显式 --docs 优先，否则探 docs / 文档 / documentation | main 解析参数后第一件调它 | 找不到返回 None，由 main 报错退出码 2，不假装找到 | 所有 build 与 check 的落点；返回值决定 arch_dir 与两处路径 |
| arch_dir | 定架构层目录，层名从 _schema.json 读，让生成物跟着层结构走 | main 拿到 docs 后调 | 配置缺失或读坏就退回 docs/10-架构，不换地方也不报错 | 旁注源与地图的落点，进而 main 的陈旧比较与 build 写盘 |
| module_functions | 定「什么算一个函数」：模块级函数加类方法，函数体内嵌套的不收 | scan_module 建函数清单时调 | 不抛；只扫 tree.body 顶层 | 函数清单本身：速查表行、覆盖校验、入口可达计数全按它算 |
| names_in | 抽函数体里的调用与引用，是调用边和对象用法的原料 | scan_module 逐函数调；render 算类与常量的用户也调 | 不抛；属性调用按短名收，运行时动态派发抽不到 | 调用图、「谁调我」与「我调谁」列、对象速查表、reach 结果 |
| scan_module | 一个脚本的结构快照：函数、调用边、反向边、类、常量、重复定义、子命令 | load_modules 逐文件调 | 语法错抛 SyntaxError 交 main 兜（退出码 2）；读文件 OSError 未捕获 | build 与 check 的全部事实来源；字段改名同时波及 render 与 check_all |
| parser_subs | 冒出 argparse 建了哪些子命令，用来和入口表的人工声明对账 | scan_module 扫完结构后调 | 不抛；没有 add_parser 调用就返回空列表 | check_all 第 5 类「入口表没登记」提醒；只提醒不阻断 |
| reach | 从入口函数沿调用边做传递闭包，回答这条命令摸到多少函数 | render 画入口表时按处理函数调 | 不抛；用 seen 防环，函数不在表里得空集 | 入口表「从它出发可达」列；依赖 scan_module 的调用边 |
| split_row | 按未转义竖线切表格行并还原转义，旁注里的竖线不被当分列 | read_notes 逐行解析时调 | 不抛；奇形行照切，退格由下游补 | 旁注四格的解析；口径要和 devlog / doc_check 一致（ISS-070） |
| is_sep | 判一行是不是表头分隔行，跳过它不误当数据 | read_notes 读每行表格时调 | 不抛；空单元格不算分隔成分 | 旁注解析结果；判错会漏掉表头行或把分隔行当旁注 |
| read_notes | 读旁注源，拆出入口表与每个脚本每函数的四格说明 | main 在 build 与 check 两路都调 | 文件不存在返回 None，不编空说明：build 报错、check 记一条错 | 全部说明文字与入口表；解析不出来 build 与 check 同时失效 |
| esc | 把单元格里的竖线转义，保证生成物表格不错列 | render 写每个说明格时调 | 不抛；空值当空串 | 生成物文本，进而 check 的逐字陈旧比较 |
| inputs_date | 给生成物定 updated：取代码与旁注里最新的 mtime，不取今天 | main 拼好路径后调 | 没有任何时间戳取今天；未来日期截到今天，避免误报陈旧 | 生成物 front-matter 的 updated 与 check 的陈旧判定 |
| render | 拼出整篇地图：总览、每脚本入口链、函数速查表、对象速查表 | main 在 build 与 check 两路都调，check 拿它当基准 | 不抛；缺格补空，入口点名的函数不存在就在表里标出 | 生成物全文；它一变已有地图立刻判陈旧，build 与 check 同时受影响 |
| check_all | 一次性判五类问题：缺旁注源、覆盖、悬空、重复定义、入口表对不上 | main 每次运行都调，build 只取 warnings | 返回 errors 与 warnings 不抛；notes 为 None 只报一条错 | check 的判定面与退出码、build 的提醒；改判据要同步旁注口径 |
| load_modules | 把代码目录每个 .py 扫成结构快照列表，定地图覆盖哪些脚本 | main 校验目录存在后调 | 单文件语法错抛 SyntaxError 交 main；目录已先验 | build 的脚本与函数计数、速查表与覆盖校验的范围 |
| main | 分 build 与 check 两动作：build 重写地图，check 判一致给 0 / 1 / 2 | 命令行 `python scripts/codemap.py build` 或 `check` | 输入缺失返回 2；check 有错返回 1；build 成功 0 | 整篇生成物与全部校验结论；参数与退出码是外部调用方的约定 |

### yaml_rules.py

| 函数 | 干什么 | 从哪进来 | 失败时怎样 | 改它谁被牵连 |
|---|---|---|---|---|
| frontmatter_block | 从一份 Markdown 里取出第一段 `---` 包住的 front-matter 正文 | `doc_check` 与 `self_test` 各自解析被检文件时调用 | 不抛错：没有 front-matter 就返回空串，由调用方把「空」判成「缺 front-matter」再报 | `doc_check` 的全部 front-matter 判据；`self_test` 读档案与计划也走它 |
| frontmatter_problems | 按「严格 YAML 子集」逐行检查 front-matter，返回问题清单；只管能不能被解析，不管内容对不对 | `doc_check` 的 front-matter 判据；`build.py` 体检 `SKILL.md`；`self_test` | 从不抛异常——所有问题收进返回列表，报几条由调用方决定 | 五个宿主的加载都会受它影响：判宽了坏 YAML 会装进宿主并静默丢掉整个技能，判严了会把合法写法误报成错 |
| metadata_problems | 检查 `.skill-metadata.yaml` 的结构：缩进层级、同级键重复、标量形态、块标量 | `build.py` 打包前的体检 | 同上，只返回清单不抛错；块标量只跟缩进，不判断文内容对不对 | 只影响 `.skill-metadata.yaml` 的结论；它与 front-matter 那条链共用 `_KEY` / `_BLOCK`，改共享常量会同时改到两边 |
| _plain | 判一个不带引号的值里有没有会让严格 YAML 解析失败的三样东西（`: `、行尾 `:`、` #`、制表符），命中就写一句人话进调用方给的 add | 只被 `frontmatter_problems` 调用 | 无状态、不抛错；add 是回调，收集到哪由调用方决定 | 只此一处调用，但它和 `_scalar` 判的是同一批字符，两处口径必须一致，否则 front-matter 与 metadata 会给出不同结论 |
| _scalar | 判单个标量的形态：引号是否闭合、plain 值里有没有危险字符、是否以 YAML 保留字符开头 | 只被 `metadata_problems` 调用 | 不抛错；开头是 `{` `[` `&` `*` `!` 或竖线这类 YAML 保留字符的值，会被判成不在子集内 | 只此一处调用，与 `_plain` 口径耦合（见上一行） |
