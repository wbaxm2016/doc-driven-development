# 文档组织管理规范

## 1. 每场会话的固定动作

```bash
python scripts/devlog.py new --title "主题" --scope "范围"   # 开场建档
python scripts/devlog.py check                               # 收尾：七段/字段/ISS 引用
python scripts/devlog.py index                               # 收尾：重建时间线
python scripts/plan.py check && python scripts/plan.py index  # 收尾：计划与排序视图
python scripts/doc_check.py                                  # 收尾：全库字段与链接
```

全部 0 error 才算收尾完成。新建档案在填完 §7 前会报 1 条 `S6 交接段过短` WARN，属正常。

## 2. 写文档的硬惯例

1. **一个事实一处**：出现两份定义同类内容，删弱的那份或降为 `reference`，不要两边同步维护。
2. **过程不构成约束**：会话档案 `status: snapshot` / `authority: 4`；要成为约束必须回写 `20-契约` 或新开 ADR。
3. **模板内只写纯文本路径**：模板被复制到子目录后，相对链接两头都不对。
4. **生成区不手改**：时间线、排序视图由脚本重建。
5. **`summary` ≤ 80 字**；`updated` 必须是真实日期——失真比错误更坏。
6. **结构只在一处定义**：改层、状态词、段结构，只改 `docs/_schema.json`。

## 3. 改代码时的顺序（本仓库特有）

1. 先改模板与 `references/`，再改脚本，最后改 `SKILL.md`（常驻上下文是最后一环）。
2. **新增规则必须先在 `scripts/self_test.py` 立断言**，再谈文档里怎么写——2.1.0 之前的教训是：码表写了 W4/W5，代码从未实现。
3. 改完跑 `python scripts/self_test.py`，再跑 `python build.py`（体检会拦下 front-matter 缺字段、引用不存在、包内多文件少文件）。
4. **`.skill` 是构建产物**：改了源仓库的脚本就要重新打包并提交 `dist/`，否则技能里的版本会悄悄落后。
5. `docs/` 与 `dist/` 的分界不得混淆：`docs/` 记录本项目怎么演化，`dist/` 是把能力交付给别人。

## 4. 提交约定

| 类型 | 前缀 | 触发 |
|---|---|---|
| 规则/校验变更 | `feat(check):` / `fix(check):` | 改了 `doc_check`/`devlog`/`plan` 或码表 |
| 文档体系 | `docs:` | 只改 `docs/` 或 `references/` |
| 发版 | `release:` | 改 `VERSION`、`CHANGELOG.md`、`dist/` |
| CI | `ci:` | 只改 `.github/` 或 pre-commit |

一次提交只做一件事；版本号与 `CHANGELOG.md` 同一次提交进。
