## 3. AI 侧记录

### 3.1 需求理解

三点合起来是一个很清楚的取舍：**机器只保「终稿引用了你说过的话」，人保「你真的复述过、真的理解了」**。判据必须进包内——否则换一端就没有；但复述动作本身没法机器判，所以不设强制字段，改成「依据必须引用可查」。

### 3.2 实现思路

1. 先立断言：第 56 组 3 条——依据引用本档原话 → 0；引用查不到 → `S12`；没引号 → `S12`。
2. 跑一次确认红（288/290）。
3. 改 `devlog.py`：`_without_decision_section()` 去掉 §4 再查；`check_decision_review()` 对用户拍板块要求 `「…」` 引用，且每句在 §4 外的正文逐字可查。
4. 回归：旧的第 24 组「补上依据 + 撤销条件 → 0」因新规则变红（它的依据没引用本档原话），给该 fixture 补一句 §2 原话——这是「测试跟着规则走」，不是放宽。
5. SKILL 加复述门条款（必过：发版 / 回滚、方向、边界、契约口径；可免：纯实现选择）；模板 §4 加 `**复述**：` 行。
6. 全量 290/290；发版 2.9.8（sha256 `4c054c5e…`），装 5 端 缺 0 / 不等 0。

## 4. 决策与选项对比

### D1 · 复述门怎么落

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 依据引用可查（选中） | 高：机器保「有据可查」 | 低：1 函数 + 3 断言 | `devlog` + SKILL + 模板 | 高 | 好 | 中 | 高：三态断言 | 引用仍可能是拼的 |
| B 强制复述字段 | 中 | 中 | 模板 + 检查 + 存量 71 块 | 中 | 中 | 低 | 低：填空壳也能过 | 形式主义 |
| C 只引用外部技能 | 低：别的端没有 | 0 | 无 | 高 | 差 | 无 | 无 | 换一端就失效 |
| D 不做 | 低 | 0 | 无 | — | 差 | 无 | — | 把模型措辞当用户结论 |

**结论**：A + 判据内置 + 每次。用户三点答复一致指向这一条。
**是否暂定**：否
**拍板**：用户
**依据**：「现在国内主流的agent…每次都需要」（三点答复：按推荐 / 判据进 SKILL / 每次都要）
**复述**：要点 ①按 A 方案（依据引用可查）②判据写进 SKILL，不能只引用外部插件 ③每次用户拍板都做复述
**撤销条件**：若出现「依据引用了、但结论仍被双方理解成两回事」的真实案例，说明引用这一半不够，改为 B（强制复述要点）或引入更强的复述校验。
