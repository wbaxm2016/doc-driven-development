## 3. AI 侧记录

### 3.1 需求理解

用户要的是「可改进」的窗口：同一问题在后续会话里是否再次出现、出现几次、跨版本有没有变化；不是一次运行的质量报告，也不是技能整体评分。

**与用户原话的偏差（显式核）**：用户说「跨会话」，我先前写「跨 run」。记录单位是 run，会话是上一层；两者在「同一场里重试 3 次」时计数不同。按 A 方案：视图按 run 时间线排，不机械分组，人可看出跨会话；若要按会话计数，需 B（加会话标识，动写路径）。已记 D1。

**第二处偏差**：「同一问题」不是「同一个 key 字符串」。现有 key 是「码:组件」，会把同码不同目标并成一条；D2 定为「码 + 目标文件」，行号不参与身份，版本是维度。

**设计门（2026-11-07，用户「按A」）**：5 条不同轴方案（新子命令 / 扩展 `status` / 写时索引 / 静态报告 / 不做），选 A——新只读子命令 `observe trend`，读时按「码 + 目标文件」聚合；落 REQ-036 / F-045 / W26.3 / K29 / T26.3.1。

**实现（2026-11-07）**：`trend` 上线；第 64 组 9 条（330→339）先红后绿；本仓真实记录上 `trend` 出 1 条 `S9:?`（目标未知）。F-045 实施中；对照 / 考核 / 发版未做。

## 4. 决策与选项对比

### D1 · 可改进视图的会话粒度与只读边界

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 按 run 时间线、纯只读（选中） | 能看见跨时间复发；不区分同场重试与会话复发 | 低 | 只读查询 | 高（删命令即回） | 低 | 高 | 高（两次失败 run） | 同场重试会多计 |
| B 记录加会话标识、按会话分组 | 能按会话计数 | 中（改写入 + 兼容） | 写路径 + 记录格式 | 中 | 中 | 高 | 中 | 破「只读」、旧记录无会话 |
| C 不做视图 | 不回答复发 | 零 | 无 | 高 | 低 | 低 | — | 第四维停在字段承诺 |

**结论**：A。B 被否（动写路径，与「只读 + 先只做技能本身」冲突）；C 被否。
**是否暂定**：否（用户「按建议」采纳）。
**拍板**：用户
**依据**：「按建议」
**复述**：用户未逐点复述；按「按建议」记为采纳 agent 建议（A + 2/1/1）。
**撤销条件**：若同一场会话内的重试被误当成跨会话复发，或用户要求按会话计数 / 分组，则回到 B（补会话标识或按档案时间归属）。

### D2 · 「同一问题」的身份（key 粒度）

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 码 + 目标文件（选中） | 同码不同文件分开；行号漂移不拆 | 低（查询时派生或改 key） | 查询 / 字段 | 高 | 低 | 高 | 高 | 旧记录 file 为空时退化 |
| B 码 + 组件（现状） | 会把不同目标并成一条 | 零 | 无 | 高 | 低 | 低 | 低 | 复发计数失真 |
| C 码 + 文件 + 行号 | 行号一变就拆条 | 低 | 查询 / 字段 | 中 | 中 | 中 | 中 | 行号漂移造成假新增 |

**结论**：A。B 被否（同码不同目标并条）；C 被否（行号漂移拆条）。
**是否暂定**：否（用户「按建议」采纳）。
**拍板**：用户
**依据**：「按建议」
**复述**：用户未逐点复述；按「按建议」采纳 2/1/1。
**撤销条件**：若同一文件里同一码的两个不同问题必须分开（需要规则 / 片段字段），或行号成为稳定身份，则重定。

### D3 · 查询面选型

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 新子命令 `observe trend`（选中） | 完整回答次数 / 首末 / 版本 | 中（约 100 行 + 断言） | 只读查询 | 高（删命令即回） | 低 | 高 | 高（两次失败 run） | 旧记录 `file` 为空时目标未知 |
| B 扩展 `status`（少做） | 只回答有没有 | 低 | 只读查询 | 高 | 低 | 中 | 中 | 回答不了次数 / 首末 |
| C 写时索引 | 能回答，但引入写路径 | 中 | 写路径 + 索引文件 | 中 | 中 | 高 | 中 | 并发 / 损坏；破只读 |
| D 静态报告 | 能回答一次 | 低 | 生成文档 | 高 | 中 | 中 | 低 | 会过期；手工重建 |
| E 不做 | 不回答 | 零 | 无 | 高 | 低 | 低 | — | 第四维停承诺 |

**结论**：A。B 少做不足，C 破只读，D 引入同步点，E 不解决第四维。
**是否暂定**：否（用户「按A」选定）。
**拍板**：用户
**依据**：「按A」
**复述**：用户直接选定 A，未逐点复述；按采纳记。
**撤销条件**：若 `trend` 与 `show` 对同一 run 的结论不一致，或需要按会话分组，回到 B/C/D 重选并更新 K29。
