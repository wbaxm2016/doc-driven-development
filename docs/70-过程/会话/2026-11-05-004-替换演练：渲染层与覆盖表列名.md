## 3. AI 侧记录

### 3.1 需求理解

ISS-081 要的不是「改点什么」，而是**成本数据**：换掉一个部件时，要动几个文件、几条断言、调用方要不要改。所以演练的口径定为「等价替换」——替换后外部行为必须逐字节一致：一致说明部件真的解耦；不一致则说明耦合到别处，那本身就是数据。

### 3.2 实现思路

**演练 A（渲染层）**：
1. 先取基线：`plan.py tree` 与 `tree --json` 各存一份，算 sha256。
2. 把 `tree_text()` / `tree_tail()` 整体换实现——旧版是「回调式 block()」，新版是「先建嵌套结构，再用递归 `emit()` 统一画线」；数据层 `tree_build()` 与所有 `load*()` 一行未动。
3. 逐字节比对：text 与 json 的 sha256 与基线**完全一致**。
4. 跑全量：`self_test` **278/278**、`plan.py check` 0 error，**0 条断言被修改**。
5. 成本：**1 个文件（`scripts/plan.py`），+29 / −31 行**，调用方 0 处改动。
6. 还原：`git checkout -- scripts/plan.py`，再跑一次 `tree` 与基线比对，仍一致。

**演练 B（模板 / 解析耦合）**：
1. 把覆盖表列名「最近走通」改成「走通日期」——只改名字，不改语义。
2. 必须同步的引用：`assets/templates/direction.md`、`docs/00-门面/方向卡.md`、`scripts/devlog.py`（解析器按表头取列）、`SKILL.md`（说明句）——**4 处**。
3. 跑校验：`brief` 仍出 `覆盖：1/12（走通日期 2026-11-03）`；`self_test` **278/278**、`doc_check` 0 error，**0 条断言被修改**（第 52 组盯的是计数行，不盯表头）。
4. 成本：**4 个文件，0 条断言**；语义未变。
5. 还原四个文件，`brief` 回到「最近走通」。

## 4. 决策与选项对比

### D1 · 演练的验收口径

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 等价替换（输出必须逐字节一致，选中） | 高：只测「换实现不动外部」 | 低 | 小（1 文件） | 高：git checkout 即还原 | 好 | 无（不改产品） | 高：sha256 比对 | 只证明解耦，不证明「换格式」的成本 |
| B 换成另一种格式（如 Markdown） | 中：更像「换部件」 | 中 | 大（CLI / 文档 / 断言） | 中 | 中 | 低 | 高 | 格式变化会撞断言与文档，成本混进「换部件」本身 |
| C 新增一个 renderer（扩展而非替换） | 中：测的是扩展点 | 低 | 小 | 高 | 好 | 中 | 中 | 不回答 ISS-081 的「替换」 |

**结论**：A。先回答「换掉实现会不会惊动别处」；B 的成本留到真要换格式时按同一方法测。
