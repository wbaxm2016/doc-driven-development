## 3. AI 侧记录

### 3.1 需求理解

三种操作各有判据：ADDED 要「目标里没有这个编号」、MODIFIED / REMOVED 要「before 在目标里恰好一次」。前两种预期都通，REMOVED 的关键不在「删得对不对」，而在**删掉之后归档还成不成立**——这才是我要测的。

### 3.2 实现思路

1. DELTA-002 MODIFIED：改 REQ-001 的验收口径 → 根目录报 `E19`；按锚点替换、归档 → 0 error。
2. DELTA-003 ADDED：新增 REQ-003（非整数输入）→ `E19`；追加行、归档 → 0 error，但出现 `W8`「REQ-003 没有功能覆盖」。
3. DELTA-004 REMOVED：锚点就是 DELTA-003 新增的那行 → `E19`；删除该行、归档 → **`E21`：DELTA-003 的 after 在目标中出现 0 次**。
4. 结论：ADDED / MODIFIED 可用；REMOVED 与归档检查冲突。登记 ISS-088。
5. 还原：删掉 DELTA-003 / DELTA-004 的归档文件，目标文件已不含 REQ-003 → `doc_check` 回到 0/0。
