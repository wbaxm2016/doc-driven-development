D17 的走通验收是三件事（REQ-049 验收列 / 方向卡 D17 行）：任一抽 3 个动作各答得出三栏；`doc_check` 0 error；用户复述采纳该表。前两件本场可证，第三件在 2026-11-09-004 §4 D2 已过（用户答「1. AI与人的分工 2. 代价能接受」），本场只把它落进方向卡覆盖表。

### 3.2 实现思路

1. 开场 `brief` 确认 D17 是唯一「走通待补」；`flow` 只报 011 档 §3.7 与 §2 漏记，均属正常。

3. 每个动作分两步核：① 能从 SKILL 表直接读出三栏；② 找一个真实实例对得上（否则表是空话）。
4. 补一条**空状态**：抽一个表里没有的动作，确认按节首总则回落。
5. 核「一处一个权威」：vision / README 中英是否只留指针。
6. 落档：方向卡覆盖表加 D17 行 + 上方条数说明；本档 §6 记证据；五连跑。

## 4. 决策与选项对比

### D1 · 走通验收按「记录类改动」处理，不新开计划任务（agent 自选）

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| **A 只补覆盖表与本档，不建计划任务** | 高：验收产出是记录，不是事实变更 | 零：一次走通 + 两处文字 | 小：方向卡一行 + 本档 | 高：删一行即回 | 低 | 无 | 高：`brief` 数字直接变 | 低 |
| B 在计划 §5 建一条「D17 走通验收」任务 | 中：任务要挂 F / W、打六维、写考核四格，为一个记录动作造一条账 | 中：五处载体 + 发版口径下的编号 | 中：计划 / FEATURES / 承接口径 | 中：删任务要同时清考核 | 高：一条纯记录长期挂在任务表 | 低 | 中 | 中：与「覆盖只记实际跑过」的定位打架 |
| C 不记录，口头说明走过 | 低：覆盖表就是唯一记分板，不记等于未覆盖 | 无 | 无 | 高 | 低 | 无 | 低 | 高：`brief` 永远报 17/18 |

**结论**：A。
**是否暂定**：否（一次做完）。
**拍板**：agent 自选。
**依据**：用户本轮「证据写进方向卡那一行」——验收产物是指向证据的记录，不是新能力；重档判据（改脚本 / 契约 / 规则 / SKILL / 方向卡核心内容）都不涉及。
**复述**：—（agent 自选）。
**为什么更合理**：覆盖表是「实际跑过的记录」（REQ-022），本场做的正是跑一遍并留证；给它开任务会把记录抬成能力，之后每跑一条方向线都要造一条任务账，与「只记实际跑过、不写计划」的定位正面冲突。B 多出的成本换不到任何判据，C 让 `brief` 继续报假缺口。
**撤销条件**：若后续出现「走通验收必须挂任务才算收口」的规则变化（例如计划要按走通次数排期），或本场的记录被考核门当作无证据驳回，就改回 B。
**被否方案**：B（回到条件：计划开始按走通次数排序，或覆盖记录需要参与考核）；C（回到条件：覆盖表被废止）。
