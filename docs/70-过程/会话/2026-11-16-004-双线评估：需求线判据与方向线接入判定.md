## 4. 决策与选项对比

### D1 · 方向线要不要补接入判定、补到哪一档

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 只写规则 + 给落点（选中） | 高：把「进入」补成可判的三问与三种结论 | S：两处规则 + 两处载体说明 | 小：SKILL / 过程记录 / 方向卡 / 模板 | 高：一条 commit 可退 | 低：不新增动作，只挪时机 | 中：回答与落点里能看见方向结论 | 中：机器只判命中，质量人读 | 低：需人判「是不是同一条方向」 |
| B 规则 + 脚本判据 | 中：进入条件是语义，脚本只能判标记 | L：新码 + 断言 + 存量豁免 | 大：脚本 / 测试 / 码表 | 中：码表变更牵连多 | 高：伪判据会长期误报 | 低 | 高（可跑） | 中：把语义判成形式 |
| C 只留人话提示，不补 | 低：落点缺失照旧 | 0 | 0 | 高 | 0 | 0 | 无 | 中：同一缺口继续靠人记得 |

**结论**：选 A——消息落点表给方向加位（`E`/`D` 的落点可写 `D-n`），并把回看三问前移到「进入方向线时」问，结论三选一；不加脚本判据。
**是否暂定**：否
**拍板**：用户 2026-11-16
**依据**：「按推荐」
**复述**：—（推荐的内容上一轮已逐条列出：加落点 / 三问前移 / 不加脚本判据；用户回「按推荐」即采纳，回退一条 commit）
**为什么更合理**：对比不补——不补时一条「用户怎么走通」的想法只能落成需求或对话结论，方向卡增长靠人记得；补后三问有固定时机与落点。放弃的是「卡写完再回看」的旧顺序，换来入口处的一次判定；代价是路由表多一段解释，仍需人判「这是不是同一条方向」。
**撤销条件**：连续两场出现「方向与需求总是同一句话被拆成两条线」，或方向落点连续三场无人使用；则退回只保留人话提示。
**被否方案**：B 加脚本判据（回到条件：出现 ≥3 次「方向接入判错」且其中至少两例能写成形式判据时）；C 不补（回到条件：这条缺口在真实会话里连续两场没有造成一次漏记时，维持现状即可）。
