## 4. 决策与选项对比

### D1 · 人读三文档怎么改

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 重构+重写语言：README 瘦身成一眼看懂，模型细节收进 vision，去重，中英同改 | 高：同时解决 AI 味与重复两个问题 | 高：三份文档重写、中英对齐 | 大：三文档全变 | 高：git revert 整体回退，不发版 | 高：一个事实一处，后续维护成本低 | 高：首屏直接变样 | 中：CI 中英同步 + 全库校验 + 人读 | 瘦身可能删掉用户重视的内容 |
| B 只改语言不动结构：保留全部章节，只去加粗 / 口号 / 排比 | 中：AI 味减，重复与「不能一眼看懂」仍在 | 中 | 中 | 高 | 低：重复仍在，违背「一个事实一处」 | 中 | 中 | 改完仍是长文 |
| C 少做：只改 README 首屏三节 | 低：vision 与英文版的 AI 味仍在 | 低 | 小 | 高 | 低：三份文档风格分裂 | 中 | 高 | 半成品 |
| D 不做 | — | 0 | 0 | — | 维持现状 | 0 | — | 用户诉求落空 |

**结论**：选 A——重构+重写语言，新手优先，围绕已确认的五条中心信息（是什么 / 给谁用 / 解决什么 / 目标 / 哲学）展开。
**是否暂定**：否
**拍板**：用户
**依据**：「优化下项目中给人看的文档的表达，现在ai味很重，去ai味。明确项目目标价值愿景然后结合实际工作的技能与代码，安排接下来的工作。」；三选一答复：改写深度=重构+重写语言、目标读者=新手优先、中心信息=确认按这个写
**复述**：要做什么＝按确认的五条中心信息重构并重写 README.md / README.en.md / vision.md，README 瘦身、细节进 vision、去重、中英同改、新手优先，改完跑中英同步与全库校验；推翻代价＝三文档不在安装包、不发版，git revert 一次整体回退，初稿可留作素材。用户答「没问题，开始」。
**为什么更合理**：回看：A 是唯一同时拔掉 AI 味与大段重复两个病根的选项——B 保留重复，同一事实两份会在后续维护里再次漂移，违背「一个事实一处」；C 让 vision 与英文版的病留着，风格分裂。改完后 README 首屏直接回答是什么、给谁用、解决什么，模型细节收敛到 vision 一处，`readme_sync.py` 与 `doc_check.py` 均 0 error，ISS-104 的定位缺口由 vision 新增「给谁用与分工」节补上。
**撤销条件**：改写后用户读首屏仍说不出「这是什么、给谁用」，或中英同步校验无法对齐且修不平——回退到 B（只改语言不动结构）。
