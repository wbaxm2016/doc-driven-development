## 3. AI 侧记录

### 3.1 需求理解

用户要的不是再加一张表，而是把「回看」从只在事后，前移到「确立之前」。他点了四处：需求确立前看系统、拆分确立前看上游、方向确立前看现状、明确之后再看「为什么这样更合理」。本场只做第一处，作为试点。

偏差（已纠正）：我此前把本技能的价值讲成「文档即唯一事实源」。用户指出那只是地基；上层价值是「判断留得住、系统走得通、完成有证据」——换人、隔月仍能决定下一步并说出为什么。

### 3.2 实现思路

1. 复用现有载体：档案 §3.3 已经承载「系统位置」，回看就写在这里，不新开表、不加第七段。
2. 形态固定三行：上游原句（逐字）/ 系统里现在有什么 / 与它哪里对不上及怎么处理。
3. 挂在「对齐门」里，不新增第六道门；机器仍只判 `确认` 在不在，三行质量人读。
4. 先试用：不写契约、不加判据；跑一两场真实需求再决定是否固化。

**系统位置**：只在「需求 → 确认」这一步生效；不影响功能 / 工作 / 任务 / 对照 / 考核；脚本零改动。

**回看（需求确立前）**：

- 上游原句（逐字）：用户「就是拆分确立前需要回看然后再确立。需求确立前也要回看系统。」
- 系统里现在有什么：对齐门只判复述 / 采纳；`E23` 只判已实现的需求有没有 `确认`；档案 §3.3 有「系统位置」但没有强制三行；没有「确立前回看」的载体。
- 与它哪里对不上：这是缺口不是重复——现有回看全在事后；处理方式是先把三行写进 §3.3 试一场，不加判据。
