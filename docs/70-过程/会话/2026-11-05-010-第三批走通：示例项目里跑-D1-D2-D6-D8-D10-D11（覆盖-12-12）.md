## 3. AI 侧记录

### 3.1 需求理解

六条线的判据都在卡片上写着，缺的是**场景**：D1 要一条未合并的 delta，D6 要一个用户拍板却缺撤销条件的决策，D8 要一条从待分诊转成 ISS 的问题，D10 / D11 要「原话 / 引文改一个字就拒收」的对照，D2 要一次轻档与一次重档。示例项目正好能造齐这些。

### 3.2 实现思路

1. **D1**：在示例里写 `DELTA-001`（ADDED REQ-002）→ `doc_check` 报 `E19`「未合并」；按锚点把 REQ-002 合并进 requirements，delta 移入 `_archive/`、status 改 snapshot → 0 error；`verify_square.py -3` → 9。
2. **D2**：轻档——改示例 README 一个措辞，只跑 `doc_check` → 0、不建档；重档——示例首场本身就是「建档 + 五连跑」。
3. **D6**：给示例会话加一个用户拍板的决策 D2（示例做多大），删掉它的「撤销条件」→ `S12` 报错；补回 → 0。
4. **D8**：`devlog ask` 记下 Q1（平方计算要不要支持负数）→ `pending --clear --as iss --relation new --type 机会` → 新增 ISS-002，待分诊清零。
5. **D10**：把示例会话 §3.7 的原话改一个字 → `E29` 拒收；改回 → 0。
6. **D11**：把 §3.8 预审引文改一个字 → `E30` 拒收；改回 → 0。
7. 六条记录写进方向卡覆盖表，`brief` 出 `覆盖：12/12`、无「走通待补」。
