## 3. AI 侧记录

### 3.1 需求理解

用户要两份文档都落，但不是复制粘贴：README 更简洁，vision 要补愿景。我的理解：`vision.md` 是定义权威，展开三条的痛点 / 机制 / 价值 / 边界；README 是入口摘要，三条各一行 + 链到 vision。

**与用户原话的偏差**：用户说的「需求 / 工作 / 任务三层」与仓库计划表的「方向 / 工作 / 任务」是两条轴（前者答「要做什么」，后者答「先做哪个」）。README 保留用户的词；vision 把两条轴都写清，避免读者把工作误当成挂在需求下。

### 3.2 实现思路

1. **先定分工**：vision = 愿景 + 三条完整定义（authority 1）；README = 三条一行摘要 + 指向 vision。README 不复制表格，避免两处同步。
2. **vision 结构**：愿景 → 三条价值（「记什么」表、两类命运表、三层表）→ 三条是一条链 → 这是什么（三载体 + 收件箱，映射三条）→ 为什么是文档 → 不做什么。删掉旧「为什么做」——痛点并入愿景与价值 #1/#2，「散文不能被校验 / 排序」的理由留在「为什么是文档」。
3. **README**：把旧的「决定记录 / 过程记录 / 下一步排序」表 + 收件箱段，换成三行 + 「治忘 / 治混 / 治乱」+ vision 链接；机制细节（ADR、六维、三视角）不再重复。
4. **术语**：vision 里写明两条轴（要做什么：需求 → 工作 → 任务；先做哪个：方向 → 工作 → 任务）与问题状态（open / deferred / done 是状态，开放 / 可关闭是命运二分）。
5. **校验**：`doc_check` 0 error；五连跑；不发版（README / vision 都是包外文件）。

## 4. 决策与选项对比

### D1 · 两份文档怎么分工

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A README 摘要 / vision 权威（选中） | 5 | 4 | 2 | 5 | 5 | 4 | 4 | 1 |
| B 两处都放完整版 | 2 | 2 | 3 | 4 | 1 | 4 | 3 | 4 |
| C 只改 README | 2 | 5 | 1 | 5 | 2 | 3 | 3 | 3 |

**结论**：选 A。用户明确要两份都落，但也明确 README 要更简洁——一份摘要一份权威，既满足「都落」，又不制造第二份定义。
**是否暂定**：否。
**拍板**：用户。
**依据**：「vision.md跟README分别落吧。README要更简洁一些」——用户本轮原话。
**撤销条件**：若 README 开始复制 vision 的表格 / 机制细节，或 vision 不再被 README 指向，分工失效，删弱的一份。

### D2 · vision 的旧「为什么做」怎么处理

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 删，痛点并入价值，另留「为什么是文档」（选中） | 5 | 4 | 1 | 5 | 5 | 3 | 4 | 1 |
| B 原样保留 | 3 | 5 | 0 | 5 | 2 | 3 | 3 | 2 |

**结论**：选 A。旧段的痛点与价值 #1/#2 重复；「散文不能被校验 / 排序」是独有的理由，留在「为什么是文档」。

### D3 · README 用「需求 / 工作 / 任务」还是「方向 / 工作 / 任务」

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A README 用需求/工作/任务，vision 解释两轴（选中） | 4 | 4 | 1 | 5 | 4 | 4 | 3 | 2 |
| B README 用方向/工作/任务 | 4 | 4 | 1 | 5 | 4 | 3 | 3 | 2 |
| C 两处都写两套 | 2 | 2 | 2 | 4 | 1 | 3 | 2 | 4 |

**结论**：选 A。保留用户原话里的三层；完整解释放 vision，README 不塞两套术语。
**是否暂定**：否。
**拍板**：agent 自选（在用户用词约束下）。
**依据**：用户原话用「需求、工作、任务」；README 是摘要，vision 负责把「先做哪个」的方向轴讲清。
**撤销条件**：若读者把 README 的三层误当成排期树（问「工作挂在需求下吗」），在 README 加一句「排期用方向 / 工作 / 任务」或改词。
