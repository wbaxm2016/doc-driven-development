## 3. AI 侧记录

### 3.1 需求理解

把 `new-feature --work-id` 的判据从「编号前缀数字 == 方向号」改成「工作存在且方向一致」：先按 §4 实际行查这个工作；不存在就 exit 1 零写入（`--work-id` 只挂已有工作）；存在但它的方向列与 `--direction` 不同也 exit 1；一致才允许在建 REQ/F/T 时沿用它的工作号。任务号由工作号推出（`W26.3` → `T26.3.1`），不再受 `D13` 的 13 限制。与用户原话无偏差。

### 3.2 实现思路

1. 读 K40 与 ISS-098，定位 `scripts/plan.py` 里 `int(m.group(1)) != dn` 这一行。
2. 把 `w_ids` 集合换成 `work_rows`（编号 → 行），这样既能判存在，也能取该行的「方向」列。
3. 分支改成：形态不对 → 拒；工作不存在 → 拒并提示「只挂已有工作，新建请省略 --work-id」；方向不一致 → 报出工作实际挂的方向；一致 → 用工作号推任务号。
4. 第 60 组补夹具：往临时计划里插 D2、W26.3（全局序号、挂 D2），往临时设计卡里插 K99；再补 3 条断言（正向挂载 / 方向不一致 / 工作不存在），并保留原 W1.1 正例与 W9.1 零写入例。
5. `self_test` 全量确认；回写计划 / FEATURES / 收件箱 / 本档；收尾五连。

## 4. 决策与选项对比

### D1 · `--work-id` 的判据怎么改

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 工作存在 + 方向一致（不存在 / 不一致都拒） | 高 | 低 | `plan.py` 一处 + 第 60 组 | 高 | 高 | 中（能挂已有工作） | 高 | 低 |
| B 不存在时按该编号新建工作（只去掉前缀判据） | 中 | 低 | 同上 | 高 | 低（可能造出重复 / 错号工作） | 中 | 中 | 中 |
| C 保留前缀判据，只对已存在工作放行 | 低 | 低 | 同上 | 高 | 低（两套规则并存） | 中 | 中 | 中 |

**结论**：选 A——`--work-id` 只挂已有工作；工作号由 §4 的行决定，不再由方向号反推。
**是否暂定**：否。
**拍板**：agent 自选（K40 已定判据，用户指令「继续 T32.1.1」）。
**依据**：T32.1.1 / K40 / ISS-098。
**复述**：—（agent 自选）。
**为什么更合理**：对比 B（不存在就新建）与被否 C（前缀 + 存在双规则）——A 把「工作号从哪来」收敛到 §4 一处，判据只有「存在 + 方向一致」两条，测试能同时给出正例与两类反例；B 会让 `--work-id` 变成第二个建工作入口，容易造出与 §4 冲突的编号；C 保留前缀判据，正是 ISS-098 的根因，且会让同一命令对不同工作走两套规则。
**撤销条件**：若出现「必须用一个尚不存在的工作号预先占位」的真实需求，或 A 让「新建工作」路径变得不可达，则改为 B（不存在时按编号新建）并另开设计卡。
**被否方案**：B（回到条件：出现预占工作号的真实需求）；C（回到条件：§4 出现无法用 A 表达的工作号规则）。
