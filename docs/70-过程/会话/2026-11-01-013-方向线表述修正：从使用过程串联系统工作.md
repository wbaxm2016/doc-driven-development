## 3. AI 侧记录

### 3.1 需求理解

用户纠正的是方向线的**定义**，不是措辞：方向线是一条从功能 / 使用过程出发、把系统工作串起来的纵切线，价值在产品使用与用户体验；「先做哪个」只是多条线并存时的选线动作，不是线的价值。

**与用户原话的偏差**：我上一版把「先做哪个」写进了标题和「回答什么」，把用法当成了定义；这一版把它降为「选线用法」，定义改成「纵切线」。

### 3.2 实现思路

1. **先核对实现**：计划 §1 说方向是「一个能被复述的成功状态」；W 的验收是「一条命令 / 一次实测 / 一份文档落地」；六维含 `U`（用户可感知），三视角含「尽快看到效果」；功能行有「验收口径（人读）」。机制支持「从使用过程出发」。
2. **改写原则**：方向线 = 纵切线（不按模块、不按需求清单，按「用户走一遍」切）；「先做哪个」= 选线用法（六维 / 三视角）；主线 / 底线的角色保留，但主线的含义改成「用户这条路」。
3. **README**：标题、开头、双线段落、认知负荷段全部改；**vision**：表、纵切线、为什么分开、「先做哪个」只是用法、主线 / 底线表。
4. **不改计划表**：D / W / T 结构与 `P12` / `P6` 保持；D1–D7 的文字不动。
5. **记一个差距**：现有 D1–D7 多数是内部能力（契约一致、决策可回顾、工具链可信），只有 D3 / D7 是用户直接感知的；这是「表达 vs 现状」的差距，另议，不在本场改。
