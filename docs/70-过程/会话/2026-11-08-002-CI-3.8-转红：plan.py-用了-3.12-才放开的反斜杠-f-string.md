## 3. AI 侧记录

### 3.1 需求理解

我把它理解成**「找出这个 job 为什么红，并从代码侧修到绿」**，而不是先降级矩阵或跳过步骤：3.12 同提交是绿的，说明坏的是「3.8 下才成立的东西」。与用户原话的偏差：用户没说落档、没说发版——落档是本仓 `AGENTS.md` 的收尾要求，发版仍留用户定（§5 ISS-102）。

### 3.2 实现思路

1. **先拿 step 级证据，不猜**：本机没有 `gh`，用 GitHub REST 匿名读 `runs/42388292238/jobs`（公开仓库，`web_fetch` 可用）。结论：3.12 全绿；3.8 在 `Verify contracts` 失败，其后 `Build & verify` / `Reproducibility` / 上传全部 skipped。
2. **把失败步还原成命令**：`python scripts/verify.py --dry-run` → 只有 2 条命令，分别是 REQ-001 的 `doc_check && devlog check && plan check` 与 REQ-002…036 共用的 `python scripts/self_test.py -v`。
3. **在本机装 3.8 复现**（不能靠「3.12 绿」推 3.8 绿）：`uv python install 3.8` 得到 `cpython-3.8.20`，装在临时目录（不污染系统）。
4. **一次性探针扫全仓**（`.tmp-run/py38scan.py`，用完删）：对 `scripts/`、`assets/`、`tests/`、`.github/scripts/`、`build.py` 逐个 `ast.parse(..., feature_version=(3,8))`，同时扫 3.9+ 标准库 API 与「运行时才求值的泛型下标」。命中第一条也是唯一一条硬错：`scripts/plan.py:1342` —「f-string expression part cannot include a backslash」。
5. **同类写法一起找**：`f"[^"]*\{[^}]*\\` 扫出 `plan.py` 的 1342 / 1351 / 1367 三处，都是把 `r'REQ-(\d+)'` 这类正则直接嵌在 f-string 表达式里；PEP 701（表达式内允许反斜杠）只在 3.12 放开，3.8–3.11 都是 `SyntaxError`。
6. **改法**：正则先算进局部变量（`req_seq` / `feat_seq` / `card_seq`），再格式化；改处留注释写明 3.8 约束，免得下一个人又写回去。
7. **验证（3.8 实跑，不用 3.12 代替）**：全量 parse 0 错；`plan.py check`、`doc_check --quiet`、`devlog check` 均 `errors=0`；`self_test` **339/339**。
8. **顺手核对包**：解 `dist/doc-driven-development-2.16.0.skill`，里面的 `scripts/plan.py` 仍是坏的那份 → 单列 ISS-102（本轮不重建 `dist/`，发版是用户决定）。

**是否暂定**：否。
**拍板**：agent 自选（缺陷修复，不涉产品口径；反悔是一次 `git revert`）。
