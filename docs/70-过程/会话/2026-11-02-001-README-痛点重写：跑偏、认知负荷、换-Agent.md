## 3. AI 侧记录

### 3.1 需求理解

用户认为旧版从「文档能留住什么」讲起，抽象、不像在说读者的痛。我的理解：开头 → 三痛点 → 双线，从「你被什么拖住」到「它怎么接」到「为什么这个结构能接」。

**与用户原话的偏差**：用户说切换 Agent「完全没有负担」，我写成「从重讲一遍降到读一页交接」——这是可兑现的；「完全没有负担」要求任意 Agent 打开仓库就自动加载技能，目前还要装技能 / 读文档。

### 3.2 实现思路

1. **先定叙事**：痛点（场景）→ 机制（怎么接）→ 结构（双线为什么能接）。旧版是「能力清单 → 结构」，读者要先理解产品，才能对上自己的痛。
2. **三痛点各落一个机制**：偏离主线 → 收件箱 + 方向线判断「是不是主线」；认知负荷 → 分层（任务 / 工作 / 方向）+ 写成功状态 / 验收本身在理清思路；换 Agent → 文档即状态 + 交接首行 + `brief` + 5 宿主。
3. **双线补两句**：为什么降认知负荷（方向线把系统压缩成一句话成功状态 + 当前工作验收）、AI 系统级串联（拿到方向 / 工作 / 功能行就能沿线做，不是从孤立一句「帮我实现 X」猜）。
4. **不写不可兑现的承诺**：「完全没有负担」改成「从重讲一遍降到读一页交接」。
5. **只改 README 开头到双线**；vision 不动——三条价值仍是定义权威。
