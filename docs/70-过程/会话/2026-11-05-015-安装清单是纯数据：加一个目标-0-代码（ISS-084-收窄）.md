## 3. AI 侧记录

### 3.1 需求理解

「替换成本」在这里等于：换掉清单的**数据**要不要动**代码**。清单已经把每个产品抽象成 `id / name / env / paths`，`probe()` 只认这四个字段——如果加一个目标真的只改 JSON，那这块就是可替换的，且比预期便宜。

### 3.2 实现思路

1. 基线：`install.py --list` 全文 sha `BB3384D5…`（5 个目标）。
2. 造一份临时清单：复制原 5 条 + 加 `demo`（`env: DEMO_SKILLS`，`paths: <临时目录>`）。
3. `install.py --list --manifest <临时>` → 6 个目标，demo 显示「将装」。
4. `install.py --from dist --manifest <临时>` → demo 端装成 35 文件、v2.9.6、source=dist、**缺 0 / 不等 0**。
5. 记账：代码改动 **0**、断言改动 **0**、数据改动 1 条；`--manifest` 本来就是显式接口，不需要新开关。

| 功能 / 能力 | 组件 | 代码或文档位置 | 对应 REQ / ADR | 依赖 / 被依赖 |

**系统位置**：清单是「配置」，不是「代码」——它能被替换，正因为 `install.py` 只依赖字段名。
