## 4. 决策与选项对比

### D1 · 其余三处回看用什么形态铺开

| 选项 | 语义正确性 | 实现成本 | 改动半径 | 可逆性 | 长期维护 | 用户可感知 | 可验证性 | 风险 |
|---|---|---|---|---|---|---|---|---|
| A 沿用试点形态，三处各写原载体（选中） | 高 | 低 | 小 | 高 | 低 | 中 | 人读 | 低 |
| B 集中写进档案 §3.3 一张表 | 中 | 中 | 小 | 中 | 中 | 低 | 人读 | 中（方向 / 拆分发生时还没档案） |
| C 只写进 SKILL，不落载体 | 低 | 低 | 小 | 高 | 低 | 低 | 无 | 高（写了没人填） |
| D 不做，保持只做需求一层 | 低 | 无 | 无 | 高 | 无 | 无 | 已有 | 高（缺口留在完成之后） |

**结论**：选 A。三处一次铺开，沿用「三行 / 原载体 / 人读」，不改脚本。
**是否暂定**：否。
**拍板**：用户
**依据**：「回看只做了需求，另外的还没做，都做掉」
**复述**：强制过——承接 `2026-11-08-008` D1 的复述（用户 2026-11-08「强制过复述，继续」）；本场是同一方向的既定铺设，不再重复复述。
**为什么更合理**：对比维持现状（只做需求一层）与被否备选——原载体各加一段，改动半径最小、可逆性最高；集中一张表会在方向 / 拆分发生时还没有档案，事后补写变回忆；只写 SKILL 会没人填。
**撤销条件**：三处回看连续 3 场写成空模板、答不出上游原句，且用户认为没挡住重复或冲突 → 退回只保留需求三行。
**被否方案**：B 集中档案 §3.3（回到条件：出现「建档前就要定方向」的真实场景）；C 只写 SKILL（回到条件：载体改版成本高于收益时）；D 不做（回到条件：用户认为当前缺口可接受时）。
