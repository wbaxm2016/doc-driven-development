## 3. AI 侧记录

### 3.1 需求理解

用户要的不是"再加一个技能"，而是**给一段已有能力换主人**：收尾时逐条给出决策的「背景 / 影响 / 依据 / 撤销条件」，这件事该由本技能承担——理由是分发面（本技能装 5 个产品，`decision-review` 只装 DSH）。

与用户原话的偏差（显式写出）：用户说的是"应该由它做"，**没说"删掉 decision-review"**。所以本轮只记录归属与落地路径，删除/停用另议。

### 3.2 实现思路

1. **契约层**：加 `REQ-005`（EARS 句式，状态 `待实现`），要求四处齐全 + 断链判据；`verify:` 先指向 `self_test`，实现后补组号。
2. **运行层**：加 `F-016`（状态 `待评审`，挂 `REQ-005`），并在台账下方写一节「待评审提案」，交代来源、为什么放进本技能、落地要改什么、明确不做什么。
3. **落地路径（评审门之后）**：`SKILL.md` 收尾动作加一步「决策回顾」；`references/process-recording.md` 加一节（四问 + 现查四路：台账 / ADR mtime / 待分诊 / git）；`assets/templates/adr.md` 补「依据」格指引。
4. **机器校验另开一步**：`devlog.py check` 新码——档案 §4 的决策行必须写撤销条件。与文本迁移分开，避免一次发布会话混进脚本改动。
5. **不动计划**：评审门未过不进计划，因此计划仍 26/26。
