# 问题收件箱

> **规则**：开发过程中发现的问题（缺陷 / 缺口 / 债 / 冲突 / 风险 / 机会 / 待决）**当场登记一行并继续当前话题**。用户不必在对话中回应——这是"关掉会话无负担"的前提。
> **候选不在这里**：一闪而过的念头先进待分诊（`devlog.py ask`，占 `Q` 不占 `ISS`）；分诊通过才进本表，状态从「确立」开始。
> **性质**：`可关闭` 有完成判据，修完进「已闭环」；`开放` 没有「做完」，只有「回到条件」，永远不进「已闭环」。
> **状态**：确立 → 实施中 → 实现关闭 / 拒绝；开放问题可以 `实施中 → 确立`，一轮做完回到确立，带着新的「本轮边界」。
> **依据**：每个状态都要写依据——确立写为什么是真问题；实施中写做到哪 / 卡在哪；关闭写结论与证据；拒绝写理由与重新考虑条件。机器判前缀与必填，判断仍要人读。
> **编号**：`ISS-nnn`，只增不复用；终态行必须移入下面的归档表。
> **问题链**：一条问题是另一条引出来的，在「落点」里写 `源自 ISS-nnn`（处理它时发现）或 `须先 ISS-nnn`（它不修完，这条不能推进）。`须先` 未关闭时本行只能停在「确立」；两者都会被 `devlog.py check` 判（`D11`–`D14` / `W13`），不写则不判（ADR-005）。
