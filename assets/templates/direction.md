# 方向卡

> **方向是现状的结论，不是独立的一步。** 先 `brief` 读一屏，再多轮对话把「现在有什么、卡在哪、哪些是旧账、哪些是新问题」说清楚，再把结论写成这张卡；卡没写出来，不要往计划 §3 加 `D`。
>
> **一个方向一行，内容只写在这里。** 计划 §3 只登记 `编号 / 方向 / 卡 / 依据`；同一件事不要在两张表里各写一份（硬规则 1）。
>
> **接缝是分水岭。** 写不出步骤之间的状态、权限、失败与空状态，说明这条方向还只是几个功能的拼盘。
>
> **走通验收不是一条 `verify:` 命令。** 它是在干净环境里按路径走一遍，每步记录观察结果（含失败路径、空状态、权限、重试）。`P18` 只判「现状 / 成功状态 / 走通验收」三格在不在，走没走通由人判。
>
> **路径**写 3–7 步，每步用括号标出靠哪些功能（`F-nnn`）或工作（`W-n.m`）；**不覆盖**写这次明确不做什么，防止方向悄悄膨胀成功能清单。
