# 方向卡

> **方向是现状的结论，不是独立的一步。** 先 `brief` 读一屏，再多轮对话把「现在有什么、卡在哪、哪些是旧账、哪些是新问题」说清楚，再把结论写成这张卡；卡没写出来，不要往计划 §3 加 `D`。
>
> **一个方向一行，内容只写在这里。** 计划 §3 只登记 `编号 / 方向 / 卡 / 依据`；同一件事不要在两张表里各写一份（硬规则 1）。
>
> **接缝是分水岭，但它写的是「步与步之间」，不是「模块内部」。** 上一步的输出 / 失败 / 权限 / 空状态怎么影响下一步——页面过期了谁刷新、注册失败后回填哪些字段、没权限时下一步给什么。**模块内部的异常处理归设计卡的「失败边界」**（`P19`）；写反了，方向线就退化成一张多余的纸（ISS-069）。
>
> **走通验收不是一条 `verify:` 命令。** 它是在干净环境里按路径走一遍，每步记录观察结果（含失败路径、空状态、权限、重试）。`P18` 判四格在不在（现状 / 成功状态 / 走通验收 / 接缝）、走通验收带 `@YYYY-MM-DD` 复核日、路径 / 接缝 / 走通验收里出现的 `F-nnn` / `W<n.m>` / `K<n>` 引用存在；走没走通、接缝归谁仍由人判（REQ-018）。
>
> **路径**写 3–7 步，每步用括号标出靠哪些功能（`F-nnn`）或工作（`W-n.m`）；**不覆盖**写这次明确不做什么，防止方向悄悄膨胀成功能清单。

|---|---|---|---|---|---|---|---|---|---|
| **D1** | （示例）只有落地页，注册后没有下一步 | （示例）新用户第一小时就流失 | （示例）新用户 · 从落地页开始 | （示例）「注册 → 建第一条记录 → 看到结果」全程走通 | ① 注册（F-001）→ ② 建记录（F-002）→ ③ 看到结果（F-003） | 注册成功后的空状态；记录保存失败的重试 | 团队协作、权限 | 在干净环境里按三步走一遍，每步记观察（@2026-12-31 复核） | F-001、W1.1 |

## 覆盖

> **覆盖 = 有走通记录的方向数 / 方向总数。** 只记**实际跑过**的走通验收，不记计划；`brief` 用 `覆盖：n/m` 汇总（REQ-022）。每跑完一条，把日期、结论与证据位置写进来——没有记录的方向，按未覆盖算。这张表在文件末尾，**新方向行要加进上面的主表**，不要追加到文件尾。

## 链路

> **覆盖看「本步走过没有」，链路看「步与步之间串起来没有」。** 覆盖表数的是单条方向线；这张表数的是跨组件的串联——上一步的输出进下一步、失败后谁回填、空状态与权限怎么传。
>
> **一条链路至少串起 2 个功能点（`F`）。** 只在一个功能点内部的流程不算链路，不要求写；方向（`D`）只作归属、不作门槛——同一个方向里跨组件恰恰最容易断。
>
> **`P20` 只判形式**：五格（起点 / 终点 / 涉及功能点 / 关键接缝 / 走通验收）在不在、`F` 是不是真的、走通验收带 `@YYYY-MM-DD`、引用的 `F` / `W` / `K` 存在。走没走通、接缝归谁仍人判（ADR-006）。`brief` 用它算 `链路覆盖 n/m`，并列出的「接缝待验」就是没有走通记录的链路。
