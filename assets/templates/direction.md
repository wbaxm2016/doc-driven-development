# 方向卡

> **方向是现状的结论，不是独立的一步。** 先 `brief` 读一屏，再多轮对话把「现在有什么、卡在哪、哪些是旧账、哪些是新问题」说清楚，再把结论写成这张卡；卡没写出来，不要往计划 §3 加 `D`。
>
> **一个方向一行，内容只写在这里。** 计划 §3 只登记 `编号 / 方向 / 卡 / 依据`；同一件事不要在两张表里各写一份（硬规则 1）。
>
> **接缝是分水岭，但它写的是「步与步之间」，不是「模块内部」。** 上一步的输出 / 失败 / 权限 / 空状态怎么影响下一步——页面过期了谁刷新、注册失败后回填哪些字段、没权限时下一步给什么。**模块内部的异常处理归设计卡的「失败边界」**（`P19`）；写反了，方向线就退化成一张多余的纸（ISS-069）。
>
> **走通验收不是一条 `verify:` 命令。** 它是在干净环境里按路径走一遍，每步记录观察结果（含失败路径、空状态、权限、重试）。`P18` 判四格在不在（现状 / 成功状态 / 走通验收 / 接缝）、走通验收带 `@YYYY-MM-DD` 复核日、路径 / 接缝 / 走通验收里出现的 `F-nnn` / `W<n.m>` / `K<n>` 引用存在；走没走通、接缝归谁仍由人判（REQ-018）。
>
> **路径**写 3–7 步，每步用括号标出靠哪些功能（`F-nnn`）或工作（`W-n.m`）；**不覆盖**写这次明确不做什么，防止方向悄悄膨胀成功能清单。
