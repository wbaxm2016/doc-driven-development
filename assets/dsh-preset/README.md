# Doc-Driven：DSH 里的薄模式

本目录是一个 `@deepseek-ai/dsh-agent-preset` 声明：给 DSH 加一个可选模式 `Doc-Driven`。它的全部作用是**开场那一步**——开新会话、进入开发任务时，先加载 `doc-driven-development` 技能，再按技能与项目规则推进。

## 为什么是「薄」

技能在标准模式下只出现在技能目录里（一行介绍），要不要读全文由模型自己判断。本模式把「要不要读」变成「默认读」，但**不复制任何规则正文**：

- 规则、判据、门禁只有技能一份（硬规则「一处一个权威」）。模式里再写一份，技能每发一版模式就过期，且没有任何检查能发现它过期。
- 模式里只放**触发与顺序**：加载哪个技能、什么时候加载。不写命令、不写门径、不写判据码。
- 工具集照抄 DSH 标准模式，只换 persona 前缀——不在这一层改变能力边界。

## 安装

在 DSH 里装这个 bundle，并把模式选给会话（两种方式都行）：

- 用 DSH 的插件管理：`install_bundle`，目标指到本目录的绝对路径；
- 或在插件管理界面里从本地目录安装。

装完在会话的模式选择器里应能看到 `Doc-Driven`。新开的会话才会用到新模式；已开的会话保持它启动时的组合。

## 验证

1. 装完查模式已在名册：DSH 的 `cordis_inspect` 里 `preset-doc-driven` 行处于激活状态。
2. 新开会话选 `Doc-Driven`，给一句普通的开发任务（不带技能名）；第一轮应先调用 `skill` 加载 `doc-driven-development`，再读项目现状。
3. 对照一次：同一句话在标准模式下开新会话，技能不一定被加载——这是这个模式要补的那一步。

## 加厚判据（用户 2026-11-12 确认）

先薄后厚是合理的演化路径，但**加厚只加动作，不加规则**：

| 观察到的症状 | 加在哪 | 为什么不加进 persona |
|---|---|---|
| 模型没去读技能 | 这里的 persona 前缀 | 这正是模式要解决的那一步 |
| 读了，但漏做某个动作 | 门禁 / 命令 / 开场钩子 | 规则再多也是软指令，漏做不会响 |
| 某个项目要定制 | 那个项目自己的规则文件 | 模式跨项目，定制属于项目 |
| 规则本身要改 | 技能本身 | 只有技能一处权威，改了所有宿主一起生效 |

判据只有一句：**这次加厚多出了一个需要同步的权威吗？** 多了就停——工具坏了会报错，规则句子坏了不会响。

## 不做什么

- 不做厚模式（技能正文常驻）：技能正文约七万字节，常驻等于每轮都付，且立刻变成两份权威。
- 不做工具化（把开场 / 校验动作包成命令或钩子）：除非先证明「记不住 / 跑错 / 漏跑命令」是真实痛点。
- 不把 `Doc-Driven` 设为默认模式：它只影响主动选它的会话。
- 不改技能正文、硬规则与脚本。
