# 可粘进 AGENTS.md / CLAUDE.md 的片段

把下面几节粘进项目根的 `AGENTS.md`（或 `CLAUDE.md` / `.cursor/rules`）。目的是让**任何** agent 在开场自动执行「日常三动作」，而不是依赖用户每次提醒。

```markdown
## 文档约定（docs/ 是唯一事实源）

- 每个开发会话开头：先 `python scripts/devlog.py brief` 读现状（上一场交接锚点 / 计划未完成 / 收件箱计数），再 `python scripts/devlog.py new --title "主题" --scope "范围"` 建档，按 `docs/70-过程/会话档案模板.md` 写。
- 过程中发现任何问题（缺陷/口径冲突/文档债/风险/待决/机会）：立刻在 `docs/70-过程/问题收件箱.md` 加一行，然后继续当前话题，**不要停下来问要不要处理**。要用户定的问题用 `python scripts/devlog.py ask`（收尾前 `pending --clear` 分诊；未清完，下一场 `new` 会被拒）。
- 收尾五条命令，全部 0 error 才算完：`devlog.py check` → `devlog.py index` → `plan.py check` → `plan.py index` → `doc_check.py`（全库校验放最后：先重建生成区，再校验重建后的产物）。
- 一个事实只有一处：出现两份定义同类内容，删弱的那份或降为 `reference`，不要两边同步维护。
- 过程档案（`status: snapshot` / `authority: 4`）**不是约束**；要成为约束必须回写契约或新开 ADR。
- 状态只被证据推进：`已实现（未验收）` ≠ `已完成`。
- 生成区（时间线、排序视图）不手改，由脚本重建。
- 「下一步做什么」只看 `docs/00-门面/开发计划.md`，别处不写排期。

## 设计讨论：先广度后深度，保留可切回

- 用户提议的方案是备选、是参考，不是讨论的边界；先把可选空间摆开，再进入细化。
- 先广度：尽可能把所有可行路径摆出来（下限 3 个、含一个「少做 / 不做」、不设上限；不同路径落在不同轴上，不是同一方案的三档）；先有发现的广度，才有选择的深度。
- 再深度：深度设计关键要点（接口 / 可替换点 / 失败边界 / 验收）；深度不是一次收敛，允许自由探索，随时回到之前的设计，不把已选方向当成不可逆。
- 被否方案不删，记「回到条件 / 触发信号」；新证据出现时允许切回，比较表增量更新，不重开一张。
- 重要设计 / 边界决策在落档前过复述门：只核两件事——要做什么、做错后推翻代价多大；不考术语。用户可回「强制过：原因」过门，原因必须写清为什么现在必须过、担心什么。

## 编辑与批量重构

- 同一模式要在多处（≥3 处）重复改时，先出**精确编辑清单**——每条写清文件、位置（锚点或行号）、旧文本 → 新文本，先贴进会话（或落盘）再动手；再写一次性脚本（模板 / 正则替换 / 批量写）一趟应用，同一变体只写一次规则；应用后核对 diff：清单内的每条都命中、清单外的文件不动，对不上先修脚本再重跑，不用手改补漏。只改一处、或探路性改动不在此列。
```

## 为什么要这一段

`SKILL.md` 只在技能被激活时进上下文；而「开场建档、收尾四连跑」这类**习惯**需要在每个会话都生效。写进 `AGENTS.md` 是把它从「需要被想起的技能」变成「默认加载的约束」——这是这套体系能不能活过半年的分水岭。
